# 7.1a — Formato 3D en `shared`

Lee antes: `docs/plan/fase-7-modo-3d.md` (§«Normas comunes») y `docs/specs/27-modo-3d.md` §2, §3,
§4 y §6.4.

## Qué entrega

El `RoomPackage` admite salas 3D, el validador las comprueba, existe el catálogo de modelos del
pack (vacío por ahora), la sala de espera por defecto funciona en 3D y la dimensión de una sala
queda fijada en la base de datos al crearla. No hay nada visible para el usuario todavía.

Solo se toca `packages/shared` y `packages/env`.

## 1. Esquemas

### 1.1 `packages/shared/src/schemas/limits.ts`

Añadir:

```ts
export const MAX_WORLD3D_PIECES_PER_ROOM = 4000;
export const MAX_WORLD3D_HEIGHT = 32;
export const MAX_WORLD3D_CUSTOM_MODELS = 40;
export const MIN_SCALE_3D = 0.1;
export const MAX_SCALE_3D = 10;
export const MAX_MODEL3D_COLLIDERS = 16;
export const MAX_MODEL3D_CLIPS = 32;
```

### 1.2 `packages/shared/src/schemas/world3d.ts` (nuevo)

```ts
export const ROOM_DIMENSIONS = ["2d", "3d"] as const;
export const RoomDimensionSchema = z.enum(ROOM_DIMENSIONS);
export type RoomDimension = z.infer<typeof RoomDimensionSchema>;

/** Dimensión efectiva: ausente = "2d". */
export function dimensionOf(meta: { dimension?: RoomDimension }): RoomDimension;

const coord = z.number().finite().min(0).max(MAX_GRID_DIMENSION);
const height = z.number().finite().min(0).max(MAX_WORLD3D_HEIGHT);
const yaw = z.number().finite().min(0).lt(360);
const scale = z.number().finite().min(MIN_SCALE_3D).max(MAX_SCALE_3D);

export const Transform3DSchema = z.object({
  x: coord, y: coord, h: height, yaw, scale: scale.optional(),
});

export const PIECE_ID_PATTERN = /^p-[a-z0-9]{8}$/;

export const Piece3DSchema = z.object({
  id: z.string().regex(PIECE_ID_PATTERN),
  model: z.string().regex(ID_PATTERN),
  x: coord, y: coord, h: height, yaw, scale: scale.optional(),
});

export const Collider3DSchema = z.discriminatedUnion("type", [
  z.object({ type: z.literal("box"),
    cx: z.number().finite(), cy: z.number().finite(), ch: z.number().finite(),
    sx: z.number().positive(), sy: z.number().positive(), sh: z.number().positive() }),
  z.object({ type: z.literal("ramp"),
    cx: z.number().finite(), cy: z.number().finite(),
    sx: z.number().positive(), sy: z.number().positive(),
    h0: z.number().finite().min(0), h1: z.number().finite().min(0),
    dir: z.enum(["x+", "x-", "y+", "y-"]) }),
]);

export const Model3DSizeSchema = z.object({
  w: z.number().positive(), d: z.number().positive(), hgt: z.number().positive(),
});

/** Modelo subido por el creador (specs/27 §9). */
export const CustomModel3DSchema = z.object({
  ref: z.string().min(1).max(MAX_INTRO_MEDIA_REF_LENGTH),
  label: z.string().max(200),
  size: Model3DSizeSchema,
  colliders: z.array(Collider3DSchema).max(MAX_MODEL3D_COLLIDERS),
  clips: z.array(z.string().max(64)).max(MAX_MODEL3D_CLIPS),
});

export const Room3DSchema = z.object({
  pieces: z.array(Piece3DSchema).max(MAX_WORLD3D_PIECES_PER_ROOM),
});

export const World3DSchema = z.object({
  rooms: z.record(z.string(), Room3DSchema),
  models: z.record(z.string().regex(ID_PATTERN), CustomModel3DSchema),
});

/** `position` derivada de un `transform` (specs/27 §3.1). */
export function positionFromTransform(t: { x: number; y: number }): Position {
  return { x: Math.round(t.x), y: Math.round(t.y) };
}
```

Exportar los tipos inferidos (`Transform3D`, `Piece3D`, `Collider3D`, `Model3DSize`,
`CustomModel3D`, `Room3D`, `World3D`). Reexportar el módulo desde `schemas/index.ts`.

El tope de 40 modelos propios (`MAX_WORLD3D_CUSTOM_MODELS`) lo comprueba el validador, no el
esquema.

## 3. Validador

### 3.1 `packages/shared/src/validator/checks3d.ts` (nuevo)

`export function checkWorld3D(pkg: RoomPackage): ValidationIssue[]` (errores) y
`export function checkWorld3DModels(pkg: RoomPackage, catalog?: Models3DCatalog): ValidationIssue[]`
(avisos).

`checkWorld3D`, si la sala es **2D** (`dimensionOf(pkg.meta) === "2d"`):

| Código | Condición |
|---|---|
| `dimension_field_in_2d` | Hay `world3d`, o algún objeto con `transform`, o algún spawn con `h`/`yaw`, o alguna antorcha con `h`. Un issue por caso, con el id afectado. |

Si la sala es **3D**:

| Código | Condición |
|---|---|
| `world3d_missing` | Falta `world3d`. (Si falta, no seguir con el resto.) |
| `layers_in_3d` | Alguna habitación tiene `layers` o `decorations` no vacíos. |
| `world3d_unknown_room` | Una clave de `world3d.rooms` no es una habitación de `map.rooms`. |
| `transform_missing` | Un objeto no tiene `transform`. |
| `transform_position_mismatch` | `object.position` ≠ `positionFromTransform(object.transform)`. |
| `out_of_bounds_3d` | Un `transform` de objeto o una pieza tiene `x` fuera de `[0, grid.cols]` o `y` fuera de `[0, grid.rows]` de su habitación. |
| `piece_id_duplicate` | Dos piezas del paquete comparten `id`. |
| `footprint_in_3d` | Un objeto declara `footprint`. |
| `custom_models_limit` | `world3d.models` tiene más de `MAX_WORLD3D_CUSTOM_MODELS` entradas. |

`checkWorld3DModels` (solo salas 3D; `catalog` por defecto `getModels3DCatalog(pkg.map.tileset)`):

| Código | Condición |
|---|---|
| `unknown_model` | Un `piece.model`, un `object.sprite` o el sprite de un estado no se resuelve con `resolveModel3D`. |
| `unknown_clip` | Un estado declara `animation` y el modelo de ese estado no trae ese clip. |

Mensajes en castellano, con el mismo tono que los de `checks.ts`.

### 3.2 `packages/shared/src/validator/validate.ts`

Registrar dos comprobaciones junto a `geometryCheck`, con el mismo patrón `check(...)`:

- `"world3d"`, severidad `"error"`. Bien: «Mundo 3D íntegro». Mal: «Mundo 3D: N problema(s)».
- `"world3d_models"`, severidad `"warning"`. Bien: «Modelos 3D conocidos». Mal: «Modelos 3D
  desconocidos: N».

En una sala 2D sin campos 3D las dos pasan sin issues.

No tocar `checkGeometry`: en 3D sigue comprobando `position`, spawns y antorchas contra `grid`.

## 4. Sala de espera por defecto en 3D

`packages/shared/src/schemas/lobby.ts`: `withLobbyRoom(pkg)` genera hoy una sala de espera con
capas de tiles. Para una sala 3D sin habitación `kind: "lobby"` debe generar, en su lugar:

- Habitación con el id que ya calcula la función, `kind: "lobby"`, `grid: { cols: 8, rows: 8 }`,
  `layers: []`, `decorations: []`, `lighting` como hoy (las luces ambiente de la habitación
  inicial).
- `spawnPoints`: `min(8, players.max)` puntos en dos filas centradas (`y = 3.5` y `y = 4.5`,
  `x = 2.5, 3.5, 4.5, 5.5`), con `h: 0` y `yaw: 0`.
- En `world3d.rooms[<id>].pieces`: una pieza `suelo-piedra-1` por cada celda interior (de
  `(1,1)` a `(6,6)`) en `(i + 0.5, j + 0.5, 0)` y un bloque `muro` por cada celda del perímetro.
  Ids deterministas: `p-` + el índice en base 36 rellenado con ceros a 8 caracteres.

El resto del `world3d` del paquete no cambia. En 2D la función se comporta exactamente como hoy.

## 5. Mecánicas de posición con altura

`packages/shared/src/session/room-session.ts`:

- `RoomPlayerPosition` gana `h?: number` y `yaw?: number`.
- `movePlayer(playerId, roomId, x, y, now = this.now, extra?: { h?: number; yaw?: number })`:
  sexto parámetro opcional nuevo; las llamadas existentes no cambian. Guarda `h` y `yaw`.
- `spawnPlayer` copia `h` y `yaw` del `spawnPoint`.
- Al migrar la posición de un jugador (`oldPlayerId` → `newPlayerId`) se conservan.
- Placas y mirillas: donde hoy se usa `isOnCell(position, plate.x, plate.y)` y `viewpointAt(...)`,
  añadir, **solo si la sala es 3D**, que `|position.h − objeto.transform.h| ≤ 1` (con `0` cuando
  falte alguno). El objeto es el `objectId` de la placa o de la mirilla.

## 6. Dimensión fija en la base de datos

### 6.1 Migración

`packages/shared/prisma/schema.prisma`, modelo `room`:

```prisma
/// Modo 3D (specs/27 §3.3): fijada al crear la sala; nada la cambia después.
/// CHECK manual `ckRoomDimension` (dimension IN ('2d','3d')), no representable en Prisma.
dimension String @default("2d")
```

Migración nueva `packages/shared/prisma/migrations/<timestamp>_room_dimension/migration.sql`,
escrita a mano siguiendo `docs/reference/migraciones-prisma.md` (nunca `prisma migrate dev`):

```sql
ALTER TABLE "room" ADD COLUMN "dimension" TEXT NOT NULL DEFAULT '2d';
ALTER TABLE "room" ADD CONSTRAINT "ckRoomDimension" CHECK ("dimension" IN ('2d', '3d'));
```

### 6.2 Borradores (`services/room-draft.ts` y sus dos stores)

- `createDraft(actor, input)`: `input.dimension?: RoomDimension` (por defecto `"2d"`).
- `store.createRoom({ authorId, title, dimension })` en el store de Prisma y en el de memoria.
- `DraftRoomRef` y lo que devuelva `findRoom` incluyen `dimension`.

### 6.3 Publicación (`services/room-publish.ts` y sus stores)

`PublishRoomRef` (lo que devuelve `store.findRoom`, en el store de Prisma y en el de memoria)
gana `dimension`. Al publicar, justo después de la comprobación de `packageFormat`
(`SUPPORTED_PACKAGE_FORMATS`), si `dimensionOf(draftPackage.meta)` no coincide con
`room.dimension`, lanzar un `RoomPublishError` con el mismo código que esa comprobación y el
mensaje «La dimensión del
documento (X) no coincide con la de la sala (Y)».
