# 7.5c — Runtime 3D: modo edición

Lee antes: `docs/plan/fase-7-modo-3d.md` (§«Normas comunes»), `docs/specs/27-modo-3d.md` §8, y
los briefs `7.5a-runtime-3d.md` y `7.5b-runtime-tactil-observador-calidad.md`. Lee entero
`packages/game-runtime/src/three/`.

## Qué entrega

`RoomRuntime3D` con `mode: "edit"`: el lienzo que usará el editor 3D (encargo 7.7). Pinta la
sala desde el modelo, se actualiza cuando el modelo cambia, informa de dónde apunta el puntero,
muestra la selección y permite mover, girar y escalar con gizmos. **No escribe en el documento**:
solo emite eventos; quien llama a los comandos del documento es el editor (7.7).

Solo se toca `packages/game-runtime/src/three/` y sus tests. Ninguna interfaz en `packages/web`.

## 1. Opción y diferencias con el modo juego

`RoomRuntime3DOptions.mode?: "play" | "edit"` (por defecto `"play"`). En `"edit"`:

- Sin avatar, sin jugadores, sin navmesh de juego, sin entrada de juego, sin `avatar-move`, sin
  resaltado por proximidad, sin calidad automática (calidad fija alta, sin sombras).
- Se pintan **todos** los objetos, también los que están en estado `"oculto"` (al 40 % de
  opacidad).
- Los métodos de juego (`placeAvatar`, `walkTo`, `walkToObject`, `dropItemAt`,
  `interactHighlighted`, `setPlayers`, `setObserverCamera`) no hacen nada.
- `observer` y `mode: "edit"` a la vez: lanza `Error`.

## 2. Cámara de editor (`camera.ts`)

Órbita alrededor de un **pivote** en el plano de trabajo (no de un avatar):

| Entrada | Efecto |
|---|---|
| Arrastre con botón derecho, o con botón central | Gira (azimut y elevación 5°–89°) |
| Arrastre con botón izquierdo manteniendo Espacio, o Mayús + botón derecho | Desplaza el pivote por el plano de trabajo |
| Rueda | Zoom (distancia 2–60 m, paso multiplicativo ×0,9 / ×1,1) |
| Tecla F | Centra el pivote en la selección (o en el centro de la habitación si no hay) |

El botón izquierdo sin modificadores queda libre para las herramientas (§4). Menú contextual
del navegador desactivado sobre el lienzo. Sin colisión de cámara. Estado inicial: pivote en el
centro de la habitación, distancia = `max(cols, rows) × 1,2`, elevación 50°, azimut 0.

Funciones puras nuevas: `panPivot(state, dxPx, dyPx, viewportHeightPx)` y
`zoomEditor(state, steps)`.

## 3. Modelo y plano de trabajo

```ts
/** Sustituye el modelo y repinta SOLO lo que cambió. */
setModel(model: RuntimeModel): void;
/** Altura del plano de trabajo (m). La rejilla y el picking del suelo usan este plano. */
setWorkHeight(h: number): void;
get workHeight(): number;
```

- **`setModel` incremental**: compara por id con lo que hay pintado en la habitación visible.
  Piezas: se crean las nuevas, se eliminan las que ya no están y se actualiza
  posición/giro/escala/modelo de las que cambiaron. Objetos: igual, incluidos `transform`,
  `sprite` y estado inicial. Si cambian `width`/`height` de la habitación o la lista de luces,
  se reconstruyen rejilla y luces. Si la habitación visible deja de existir, pasa a la primera.
  No hay fundido ni se mueve la cámara.
- **Rejilla**: `GridHelper` de `cols × rows` celdas de 1 m, en `h = workHeight + 0.01`, y un
  rectángulo con el contorno de la habitación. Líneas `#64748b` al 50 %.
- **Marcadores** (solo en edición):
  - punto de aparición: disco de 0,3 m de radio en `(x, h, y)` con una flecha en la dirección de
    su `yaw`, color `#22c55e`;
  - antorcha: esfera de 0,12 m en `(x, h ?? 1.6, y)`, color `#f59e0b`.
- En edición, el estado que se pinta de cada objeto es su `initialState`.

## 4. Puntero (`onEditEvent`)

```ts
export type EditTarget3D =
  | { kind: "piece"; id: string }
  | { kind: "object"; id: string }
  | { kind: "spawn"; id: string }
  | { kind: "torch"; index: number }
  | { kind: "none" };

export interface EditPointer3D {
  type: "move" | "down" | "up" | "click";
  /** Punto del plano de trabajo bajo el puntero (coordenadas lógicas), o `null` si el rayo no lo corta. */
  point: { x: number; y: number; h: number } | null;
  /** Lo que hay bajo el puntero (lo más cercano a la cámara). */
  target: EditTarget3D;
  button: number;
  shiftKey: boolean; altKey: boolean; ctrlKey: boolean; metaKey: boolean;
}

onEditEvent(handler: (event: EditPointer3D) => void): () => void;
```

- Solo se emiten para el botón izquierdo sin Espacio pulsado (lo demás es cámara) y nunca
  mientras se arrastra un gizmo.
- `click` = `down` + `up` con menos de 6 px de movimiento; se emite además de `down` y `up`.
- `point` no se ajusta a ninguna rejilla: el imán lo aplica quien recibe el evento.

## 5. Selección y fantasma

```ts
setSelection(targets: readonly EditTarget3D[]): void;        // [] = nada
/** Pieza u objeto «en la mano» que sigue al puntero antes de colocarse; `null` lo quita. */
setGhost(ghost: { model: string; x: number; y: number; h: number; yaw: number; scale?: number } | null): void;
```

- Selección: contorno `#38bdf8` (misma técnica que el resaltado de 7.5a: copia en `BackSide` a
  escala 1,04) y una caja envolvente de líneas. Los marcadores seleccionados se pintan en
  `#38bdf8`.
- Fantasma: el modelo (o su caja de sustitución) al 50 % de opacidad, sin entrar en el picking.

## 6. Gizmos

`TransformControls` de `three/examples/jsm/controls/TransformControls.js`.

```ts
export type GizmoMode = "translate" | "rotate" | "scale";
setGizmoMode(mode: GizmoMode | null): void;                  // null = sin gizmo
/** Imán: paso de traslación en m (0 = libre) y de giro en grados (0 = libre). */
setSnap(snap: { move: number; yaw: number }): void;

export interface TransformChange3D {
  target: EditTarget3D;                                     // nunca "none"
  x: number; y: number; h: number; yaw: number; scale: number;
}
/** Mientras se arrastra (cada fotograma con cambio) y al soltar (`final: true`). */
onTransform(handler: (changes: readonly TransformChange3D[], final: boolean) => void): () => void;
```

- El gizmo se engancha a la selección cuando `gizmoMode` no es `null` y hay algo seleccionado.
  Con varios elementos, se engancha a un pivote en el centro de sus posiciones y la
  transformación se aplica a todos (mover y girar alrededor del pivote; escalar, cada uno sobre
  sí mismo).
- `translate`: tres ejes. `rotate`: solo el eje vertical (`showX = showZ = false`). `scale`:
  uniforme (un solo valor; usa el eje `Y` del gizmo y aplica el mismo factor a los tres).
- Spawns: `translate` y `rotate`. Antorchas: solo `translate`. En `scale` el gizmo no se muestra
  para ellos.
- Durante el arrastre la vista se actualiza en local (sin esperar a `setModel`) y se emite
  `onTransform(..., false)`. Al soltar, `onTransform(..., true)`. Si después llega un `setModel`
  con otros valores, manda el modelo.
- Los valores emitidos ya llevan el imán aplicado, `yaw` normalizado a `[0, 360)`, `scale`
  limitado a `[0.1, 10]`, `h ≥ 0`, y `x`, `y` limitados a la habitación.

## 7. Navmesh visible

```ts
setNavmeshVisible(visible: boolean): void;
```

Con `true`, genera la navmesh de la habitación con `@escaperoom/nav3d` y la dibuja como malla
semitransparente (`#22c55e` al 35 %, 0,03 m por encima) con sus aristas. Se regenera, con un
retardo de 300 ms tras el último cambio, cuando `setModel` cambia piezas u objetos. Añade a
`@escaperoom/nav3d` lo mínimo para obtener la geometría de depuración:

```ts
// RoomNav
debugGeometry(): { positions: Float32Array; indices: Uint32Array };   // coordenadas Three (X, Y, Z)
```

(único cambio permitido fuera de `game-runtime`; con su test).

## Tests (`packages/game-runtime/test/three/`, headless)

- `camera.test.ts`: `panPivot` y `zoomEditor` (límites).
- `edit-mode.test.ts`:
  - `mode: "edit"` no crea avatar y `walkTo` devuelve `false`; `observer` + `edit` lanza.
  - `setModel` incremental: añadir una pieza crea un objeto de escena y no recrea los demás
    (compara identidades de los `Object3D` existentes antes y después); mover una pieza
    actualiza su posición; quitarla la elimina.
  - `setSelection` / `setGhost` no lanzan con ids inexistentes.
  - Expón, solo en `headless`, `simulatePointer(type, ndcX, ndcY, modifiers?)` y prueba que un
    `click` sobre el centro de un objeto da `target.kind === "object"` y que uno sobre suelo
    vacío da `point` en el plano de trabajo.
  - Expón, solo en `headless`, `applyGizmoDelta({ dx, dy, dh, dyaw, dscale }, final)` (la misma
    función interna que usa el arrastre) y prueba: el imán de 1 m redondea; `yaw` se normaliza;
    la selección múltiple gira alrededor del pivote; los límites de habitación y escala.
  - `setWorkHeight(1)` mueve el plano de picking.
- `packages/nav3d/test/`: `debugGeometry` devuelve triángulos para un suelo y arrays vacíos para
  una navmesh vacía.

## Criterios de aceptación

- `pnpm verify:pr` en verde. Los tests existentes del modo juego no cambian.
- Nada fuera de `packages/game-runtime/src/three/`, `packages/nav3d` (§7), sus tests y este
  brief.
