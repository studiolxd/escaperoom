# 7.9 — MCP 3D

Lee antes: `docs/plan/fase-7-modo-3d.md` (§«Normas comunes»), `docs/specs/27-modo-3d.md` §3, §4 y
§8.2, y `docs/specs/10-mcp-del-creador.md`. Requiere 7.1b integrado.

## Qué entrega

Un agente puede crear una sala 3D y construir su mundo solo con herramientas del MCP: las mismas
operaciones que hará el editor (ADR-010), sobre los comandos de `@escaperoom/editor/room-doc`.

Solo se toca `packages/mcp-server` y, para inyectar el interruptor, donde `packages/web`
construye las dependencias del MCP.

## 1. Interruptor

`CreatorMcpDeps` (`src/deps.ts`): `rooms3dEnabled?: boolean` (por defecto `false`). `packages/web`
lo rellena desde `@escaperoom/env` (`ROOMS_3D_ENABLED`) donde construye las dependencias del MCP
(HTTP y stdio).

## 2. `create_room` (`src/tools/create-room.ts`)

- `MetaInputSchema`: añadir
  `dimension: RoomDimensionSchema.optional().describe('"2d" (por defecto) o "3d". No se puede cambiar después de crear la sala.')`.
- Si `dimension === "3d"` y `!deps.rooms3dEnabled` → `ToolError("NOT_AVAILABLE", "Las salas 3D
  aún no están disponibles")`.
- Pasar `dimension` a `writeRoomMeta` (ya va dentro de `meta`) y a
  `deps.drafts.createDraft(actor, { title, dimension, initialUpdate })`.
- Texto de éxito en 3D: «Siguiente paso: define_subrooms y place_pieces.»
- Añadir a la `description`: «`dimension`: "2d" (isométrica, por defecto) o "3d" (tercera
  persona); fija para siempre.»

## 3. Herramientas 2D en una sala 3D

`set_map`, `paint_tiles` y `decorate_subroom` ya fallan en 3D porque sus comandos lanzan
`RoomDocError("WRONG_DIMENSION")`. En `roomDocErrorToToolError` (`src/draft-writer.ts`), traducir
ese código a `ToolError("INVALID_INPUT", ...)` con el mensaje del error más:

- en una sala 3D: « Esta sala es 3D: usa place_pieces, update_pieces, remove_pieces, move_object
  y set_spawn_points.»
- en una sala 2D: « Esta sala es 2D: usa set_map, paint_tiles y decorate_subroom.»

(`details.reason = "WRONG_DIMENSION"`.) La dimensión se lee con `roomDimension(doc)`.

`set_map` solo con `tileset` (sin `size` ni `layers`) sí vale en 3D: elige el pack. Comprueba
que `setTileset` no esté entre los comandos vetados en 3D por 7.1b; si lo está, es un error de
7.1b: avisa a la coordinadora.

`UNKNOWN_PIECE` → `ToolError("NOT_FOUND", ...)`.

## 4. Herramientas existentes que cambian su descripción

Solo el texto de `description` (los esquemas ya admiten los campos nuevos):

- `define_subrooms`: añadir «En una sala 3D, `bounds.w × bounds.h` son metros, y los
  `spawnPoints` llevan además `h` (altura) y `yaw` (giro en grados).»
- `add_object`: añadir «En una sala 3D es obligatorio `object.transform` (`x`, `y`, `h` en
  metros, `yaw` en grados, 0 = mirando al sur); `position` se calcula sola a partir de él, y
  `sprite` y los estados nombran modelos de `get_model_catalog`.»
  En el texto de éxito, si hay `transform`, mostrar `(x, y, h) yaw°` en lugar de la celda.

## 5. Herramientas nuevas

Un archivo por herramienta en `src/tools/`, con `defineTool`, `mutateDraft` y `mutationResult`
como `add-object.ts`. Todas con `roomId: RoomIdSchema` y `dryRun: DryRunSchema`; `ticket: "7.9"`.
Registrarlas en `CONTENT_TOOLSET` (`src/tools/index.ts`), en el orden de la tabla, después de
`defineSubroomsTool` las de fase `structure` y después de `decorateSubroomTool` las de `content`.

Esquema común de pieza de entrada:

```ts
const PieceInputSchema = Piece3DSchema.omit({ id: true });   // model, x, y, h, yaw, scale?
```

| Herramienta | Fase | Entrada (además de `roomId`, `dryRun`) | Comando | Texto de éxito |
|---|---|---|---|---|
| `place_pieces` | structure | `subroomId: string`; **uno** de: `pieces: PieceInputSchema[]` (1–500) o `fill: { model, from: {x,y}, to: {x,y}, h, yaw? }` (enteros en `from`/`to`) | `placePieces3D` / `fillPieces3D` | `✅ place_pieces — N pieza(s) en "<subroomId>"` + `structuredContent: { roomId, subroomId, ids }` |
| `update_pieces` | structure | `updates: { id, model?, x?, y?, h?, yaw?, scale? }[]` (1–500) | `updatePiece3D` por cada una, en una sola transacción | `✅ update_pieces — N pieza(s) actualizadas` |
| `remove_pieces` | structure | **uno** de: `ids: string[]` (1–500) o `subroomId` + `model?` (borra todas las de esa habitación, o solo las de ese modelo) | `removePieces3D` (para la segunda forma, `listPieces3D` y filtrar) | `✅ remove_pieces — N pieza(s) borradas` |
| `set_spawn_points` | structure | `subroomId`; `spawnPoints: { id, x, y, h, yaw }[]` (1–8) | `setSpawnPoints3D` | `✅ set_spawn_points — N punto(s) en "<subroomId>"` |
| `move_object` | content | `objectId`; `transform: Transform3DSchema`; `subroomId?` (cambiar de habitación) | `setObjectTransform` | `✅ move_object — "<id>" en (x, y, h) yaw°` |
| `get_pieces` | query | `subroomId`; `model?` | `listPieces3D` (lectura con el mismo lector de borradores que `get_room`) | lista `id model x y h yaw`, una por línea, y `structuredContent: { pieces }` |
| `get_model_catalog` | query | `category?` (una de las de `Model3DEntry`) | `getModels3DCatalog(tileset)` + `world3d.models` del borrador | por modelo: `id — categoría — w×d×hgt m — snap — clips`; `structuredContent: { models }` |

Reglas:

- `place_pieces` y `remove_pieces`: si llegan las dos formas o ninguna →
  `ToolError("INVALID_INPUT", ...)` diciendo que hay que elegir una.
- `place_pieces` con `fill`: añadir a la descripción que las piezas van al centro de cada celda
  (`x + 0.5`, `y + 0.5`) y que no sustituye lo que ya haya.
- `get_pieces` y `get_model_catalog` usan `READ_ONLY`. Si `get_pieces` superaría el tope de
  tamaño de respuesta del MCP, el error existente (`RESPONSE_TOO_LARGE`) ya lo cubre: añade a su
  descripción «filtra por `model` si la habitación tiene muchas piezas».
- `get_model_catalog` en una sala 2D: `ToolError("INVALID_INPUT", ...)` con el mensaje de §3.
- Descripciones en castellano, con el mismo nivel de detalle que las existentes: qué hace,
  unidades (metros, grados), el convenio de `yaw` y qué herramienta usar a continuación.

`docs/specs/10-mcp-del-creador.md` §2: añadir las siete herramientas a la tabla del toolset, y

## Tests (`packages/mcp-server/test/`)

`world3d-toolset.test.ts`, con los helpers de `content-toolset.test.ts` y `rooms3dEnabled: true`:

- `create_room` con `dimension: "3d"` crea el borrador y `get_room` devuelve `meta.dimension`.
- Con `rooms3dEnabled: false` → `NOT_AVAILABLE`.
- Guion completo: `create_room` 3D → `define_subrooms` (6×6) → `place_pieces` con `fill` de
  suelo (36 piezas) → `place_pieces` con una lista (4 muros) → `set_spawn_points` →
  `add_object` con `transform` → `move_object` → `update_pieces` → `get_pieces` →
  `remove_pieces` por modelo → `validate` sin errores (los avisos `unknown_model` son
  aceptables: el catálogo real está vacío hasta 7.3b).
- `paint_tiles` en la sala 3D → `INVALID_INPUT` con `reason: "WRONG_DIMENSION"` y el texto que
  remite a las herramientas 3D. `place_pieces` en una sala 2D → lo mismo, al revés.
- `dryRun: true` en `place_pieces` no escribe.
- `add_object` sin `transform` en 3D → `INVALID_INPUT`.
- El test que enumera el toolset (`server.test.ts` o `meta-toolset.test.ts`) se actualiza con
  las herramientas nuevas; `find_tools` las encuentra por «pieza» y «3d».

## Criterios de aceptación

- `pnpm verify:pr` en verde. `mcp-parity.spec.ts` (Rey Aldric 2D) pasa sin tocarlo.
- Toda mutación 3D pasa por `mutateDraft` (validador incremental y `dryRun` incluidos).
