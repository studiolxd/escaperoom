# 7.5a — Runtime 3D: mundo, avatar, cámara e interacción

Lee antes: `docs/plan/fase-7-modo-3d.md` (§«Normas comunes») y `docs/specs/27-modo-3d.md` §2, §4,
§5.3 y §7. Requiere 7.1b y 7.4 integrados (lo están).

El runtime 3D se entrega en dos encargos. **7.5a** (este) deja una sala 3D jugable con teclado y
ratón. **7.5b** (después) añade controles táctiles, cámaras de observador, calidad automática y
el modo edición. No hagas nada de 7.5b.

## Qué entrega

`@escaperoom/game-runtime/three`: una clase `RoomRuntime3D` con la misma fachada que
`RoomRuntime` (Phaser, `src/phaser/room-runtime.ts`), que pinta una sala 3D con Three.js, mueve
al avatar por la navmesh, gestiona la cámara en tercera persona y emite los mismos
`WorldSceneEvent`. No se conecta todavía a la web (lo hace 7.6).

Solo se toca `packages/game-runtime`. No toques `src/phaser/` salvo el cambio de tipo de §8.

## 0. Dependencias y estructura

`packages/game-runtime/package.json`:

- dependencies: `"three": "0.186.1"` (versión exacta, la misma que `tools/assets-generator`),
  `"@escaperoom/nav3d": "workspace:*"`.
- devDependencies: `"@types/three"` en la versión exacta que corresponda a 0.186.
- exports: `"./three": "./src/three/index.ts"`.

El índice del paquete (`src/index.ts`) **no** reexporta nada de `three/` (igual que no reexporta
`phaser/`): Three.js no debe entrar en bundles que no lo usan.

```
src/three/
  index.ts            reexporta la API pública
  room-runtime-3d.ts  fachada (clase RoomRuntime3D)
  assets.ts           carga y caché de GLB, cajas de sustitución
  toon.ts             material toon y degradado
  world.ts            construye la habitación: piezas, objetos, luces, malla de colisión
  avatar.ts           avatar (GLB con clips o maniquí), anillo, interpolación de remotos
  camera.ts           cámara en órbita (matemática pura + aplicación a THREE.Camera)
  movement.ts         seguir ruta y paso WASD (puro, sobre la interfaz RoomNav)
  proximity.ts        objeto resaltado por proximidad (puro)
  input.ts            puntero (clic frente a arrastre), rueda y teclado
```

Los módulos marcados «puro» no importan `three` ni tocan el DOM, para poder probarlos en Node.

## 1. Fachada (`room-runtime-3d.ts`)

```ts
export interface RoomRuntime3DOptions {
  initialRoomId?: string;
  /** URL base del pack (sin barra final): `/packs/medieval-v1`. Sin ella, todo son cajas. */
  packBaseUrl?: string;
  /** Catálogo del pack; por defecto `getModels3DCatalog(<tileset>)`. Los tests inyectan uno. */
  catalog?: Models3DCatalog;
  /** Tileset (id del pack) de la sala, para resolver el catálogo por defecto. */
  packId?: string;
  /** Resuelve la URL de un modelo propio (`customModels[id].ref`). Sin él, caja. */
  resolveCustomModelUrl?: (ref: string) => string | undefined;
  avatar?: boolean;                 // por defecto true
  inputEnabled?: boolean;           // por defecto true
  localPlayerId?: string;
  localCharacterId?: string;
  emitAvatarMoves?: boolean;        // por defecto false
  backgroundColor?: string;         // por defecto "#0b1120"
  /** Solo tests: no crea WebGLRenderer ni bucle de animación. */
  headless?: boolean;
}

export class RoomRuntime3D {
  constructor(parent: HTMLElement, model: RuntimeModel, options?: RoomRuntime3DOptions);
  /** Se resuelve cuando la navmesh de la habitación inicial está lista. */
  readonly ready: Promise<void>;
  get currentRoomId(): string;
  showRoom(roomId: string, onBuilt?: () => void): void;
  placeAvatar(x: number, y: number, h?: number, yaw?: number): void;
  get avatarCell(): { x: number; y: number } | undefined;      // plano lógico, con decimales
  get avatarPose(): { x: number; y: number; h: number; yaw: number } | undefined;
  setLocalTint(tint: string): void;                            // "#rrggbb"
  setLocalCharacter(characterId: string): void;
  setBackgroundColor(hex: string): void;
  setPlayers(players: readonly ScenePlayer[]): void;
  setObjectState(objectId: string, state: string): void;
  inspectObject(objectId: string): void;                       // emite `interact`
  isObjectInteractive(objectId: string): boolean;
  getObjectScreenFraction(objectId: string): { x: number; y: number } | undefined;
  setInputEnabled(enabled: boolean): void;
  dropItemAt(itemId: string, screenX: number, screenY: number): string | undefined;
  onWorldEvent(handler: (event: WorldSceneEvent) => void): () => void;
  destroy(): void;
}
```

- Si `model.dimension !== "3d"`, el constructor lanza `Error("RoomRuntime3D solo admite salas 3D")`.
- Este runtime es siempre «dirigido por motor» (lo que en Phaser es `intentOnly`): nunca resuelve
  diálogos ni paneles; solo emite intenciones.
- `ScenePlayer` y `WorldSceneEvent` se importan de `../phaser/room-scene` y
  `../phaser/world-events` **solo como tipos** (`import type`), para no arrastrar Phaser.
- `onWorldEvent` usa un emisor propio (un `Set` de manejadores); no hay `scene.events`.

## 2. Assets (`assets.ts`) y material (`toon.ts`)

- `GLTFLoader` con `MeshoptDecoder` (`three/examples/jsm/libs/meshopt_decoder.module.js`).
- Caché a nivel de módulo por URL: `Map<string, Promise<GLTF>>`. Cada uso clona la escena
  (`SkeletonUtils.clone` si tiene esqueleto; `scene.clone(true)` si no).
- URL de un modelo del pack: `${packBaseUrl}/${entry.file}`. De uno propio:
  `resolveCustomModelUrl(ref)`.
- **Caja de sustitución**: `BoxGeometry(size.w, size.hgt, size.d)` con la base en el origen
  (trasladada `hgt / 2` hacia arriba), color por categoría:
  suelo `#57534e`, muro `#78716c`, estructura `#a8a29e`, mueble `#b45309`, pared `#7c3aed`,
  suelto `#0891b2`, modelo propio `#be185d`, desconocido `#dc2626`.
  Se usa cuando: no hay `packBaseUrl`, el modelo no está en el catálogo (tamaño 1 × 1 × 1), o la
  carga falla. La caja se pinta **de inmediato** y, si luego llega el GLB, lo sustituye.
- Excepción de las piezas de suelo (`category === "suelo"`): su caja va hacia abajo (cara
  superior en el origen), como el modelo real (spec §2).
- `toon.ts`: `toToon(material)` devuelve un `MeshToonMaterial` que conserva `map`, `color`,
  `emissive` y `emissiveMap`, con un `gradientMap` de 3 bandas (`DataTexture` de 3 píxeles
  `[90, 170, 255]`, `RedFormat`, `NearestFilter`). Caché por material de origen. Copia el
  criterio de `tools/assets-generator/visor/main.js`.

## 3. Mundo (`world.ts`)

Por habitación visible se construye un `THREE.Group` con:

1. **Piezas** (`room.pieces`): un objeto por pieza en `position (x, h, y)`,
   `rotation.y = yaw · π / 180`, `scale` uniforme.
2. **Objetos** (`room.objects`): igual, con su `transform`. El modelo es el del estado actual:
   `spriteByState[state]` si existe, si no `sprite`. Mismo criterio que
   `resolveObjectStateSprite` de `src/world`.
3. **Malla de colisión** (invisible): una sola `THREE.Mesh` con la geometría de
   `buildNavInput(...)` de `@escaperoom/nav3d`. Sirve para tres cosas: la altura visual del suelo
   (§5), el clic en el suelo (§7) y la colisión de la cámara (§6).

   `buildNavInput` necesita un `RoomPackage`; el runtime solo tiene el `RuntimeModel`. Añade a
   `@escaperoom/nav3d` (único cambio permitido fuera de `game-runtime`) una función hermana:

   ```ts
   export function buildNavInputFromParts(parts: {
     pieces: readonly Piece3D[];
     objects: readonly { modelId: string; transform: Transform3D }[];   // ya filtrados: los que bloquean
     catalog: Models3DCatalog | undefined;
     customModels: World3D["models"] | Record<string, { size: Model3DSize; colliders: Collider3D[] }> | undefined;
   }): NavInput;
   ```

   y haz que `buildNavInput` la use por dentro (mismo resultado que hoy; sus tests no cambian).
   El runtime decide qué objetos bloquean con el mismo criterio que `buildNavInput`: todos menos
   `type === "puerta"`, los que tienen `leadsTo` y los `stepOn`; modelo del `initialState`.
4. **Navmesh**: `await initNav3D()` una vez y `createRoomNav(input)` por habitación; se destruye
   al cambiar de habitación y en `destroy()`.
5. **Luces**: `DirectionalLight` (dirección `(−0.7, 0.9, 0.5)`, intensidad 3) y
   `HemisphereLight(0xdfe8ff, 0x3a3530, 0.6)`. Si la habitación declara una luz `ambient`, su
   `color` e `intensity` sustituyen a los de la `HemisphereLight`. Fondo `backgroundColor` y
   `Fog` del mismo color de 12 a 30 m.
6. **Antorchas** (`lighting` de tipo `torch`): estado encendido/apagado con
   `resolveTorchLights(model, roomId, objectState)` de `src/world` (ya existe). Cada antorcha
   encendida: `PointLight(0xffb060, 2, 6)` en `(x, h ?? 1.6, y)`. Como mucho 8 `PointLight`
   activas a la vez: las más cercanas al avatar; se recalcula cuando el avatar se mueve más de
   1 m y al cambiar un estado.

**Estados** (`setObjectState`): guarda el estado, sustituye el modelo del objeto y, si
`animationByState[state]` existe y el GLB nuevo trae un clip con ese nombre, lo reproduce una
vez (`LoopOnce`, `clampWhenFinished`). Un objeto en estado `"oculto"` no se pinta
(`visible = false`) y no es interactivo, igual que en 2D (`updateInteractivity` de
`room-scene.ts`).

**`showRoom(roomId, onBuilt)`**: fundido a negro de 170 ms (un `div` superpuesto dentro de
`parent`, sin Three), reconstruye mundo y navmesh, coloca la cámara, llama a `onBuilt` y funde de
vuelta en 170 ms. Si `roomId` no existe en el modelo, lanza `Error`.

## 4. Movimiento (`movement.ts`, puro)

```ts
export const WALK_SPEED = 3.5;             // m/s
export const ARRIVE_EPSILON = 0.05;        // m

export interface Pose { x: number; y: number; h: number; yaw: number }

/** Avanza por la ruta `dt` segundos. Devuelve la pose nueva y la ruta que queda. */
export function followPath(pose: Pose, path: readonly NavPoint[], dt: number):
  { pose: Pose; rest: NavPoint[]; moving: boolean };

/** Paso de teclado: `dir` es un vector unitario en el plano lógico. Usa `nav.slide`. */
export function stepToward(pose: Pose, dir: { x: number; y: number }, dt: number, nav: RoomNav):
  { pose: Pose; moving: boolean };

/** Giro (grados, [0, 360)) de quien avanza en la dirección `(dx, dy)`: 0 = +y, 90 = +x. */
export function yawOf(dx: number, dy: number): number;     // atan2(dx, dy) en grados, normalizado

/** Gira `from` hacia `to` como mucho `maxDeg`, por el camino corto. */
export function turnToward(from: number, to: number, maxDeg: number): number;
```

- El avatar gira hacia donde avanza a 720°/s (`turnToward`).
- `h` de la pose es la de la navmesh (lógica). Es lo que se envía al servidor.

## 5. Avatar (`avatar.ts`)

- Personaje: `catalog.avatars[characterId]` → GLB con sus clips (`clips.idle`, `clips.walk`,
  `clips.interact`). `AnimationMixer`; transición de 0,15 s entre `idle` y `walk` según
  `moving`. `interact` se reproduce una vez al emitir `interact` / `use-item` /
  `interact-direct`.
- Sin entrada en el catálogo, sin `packBaseUrl` o si falla la carga: **maniquí** — una
  `CapsuleGeometry(0.3, 1.15)` con la base en el suelo, tintada con el color del jugador, y un
  cono pequeño al frente para ver hacia dónde mira.
- **Anillo**: `RingGeometry(0.32, 0.42)` tumbado a 0,02 m del suelo, del color del jugador
  (`setLocalTint` / `ScenePlayer.tint`).
- **Altura visual**: el servidor y la navmesh dan una `h` con un sesgo de hasta una celda
  (≈ 0,1 m por encima del suelo real). Para pintar, lanza un rayo hacia abajo desde
  `(x, h + 1, y)` contra la malla de colisión y usa la `h` del primer impacto; si no hay
  impacto, la `h` lógica. La pose lógica no se modifica.
- **Otros jugadores** (`setPlayers`): se pintan los de `roomId === currentRoomId` y
  `connected`. Cada uno interpola hacia su último `(x, y, h, yaw)` con suavizado exponencial
  (constante de tiempo 0,1 s); si la distancia es > 4 m, salta. Clip `walk` mientras se mueva
  más de 0,02 m por fotograma, `idle` si no. `h` y `yaw` ausentes = 0.
- `setLocalCharacter("")` (sin personaje todavía): no se pinta el avatar local.
- `placeAvatar(x, y, h?, yaw?)`: coloca la pose (ajustada a la navmesh con `nav.closest`; si no
  hay punto, tal cual) y cancela la ruta.

## 6. Cámara (`camera.ts`)

Estado: `{ azimuth, polar, distance }` y un objetivo = posición visual del avatar + 1,2 m.

```ts
export const CAMERA = {
  minDistance: 2, maxDistance: 8, startDistance: 5,
  minPolarDeg: 10, maxPolarDeg: 75, startPolarDeg: 55,   // 0° = horizontal, 90° = cenital
  rotateSpeedDegPerPx: 0.3, zoomStep: 0.5, collisionMargin: 0.2, fovDeg: 50,
} as const;

/** Posición de la cámara para un estado y un objetivo (puro, coordenadas Three). */
export function orbitPosition(state, target): { x: number; y: number; z: number };
/** Aplica un arrastre de (dx, dy) píxeles, respetando los límites. */
export function rotateOrbit(state, dxPx: number, dyPx: number): OrbitState;
export function zoomOrbit(state, steps: number): OrbitState;
/** Dirección de avance en el plano lógico para WASD, según el azimut de la cámara. */
export function cameraForward(azimuthDeg: number): { x: number; y: number };
```

- Al entrar en una habitación, la cámara se coloca detrás del avatar (`azimuth` = `yaw + 180`).
- **Colisión**: rayo desde el objetivo hacia la posición deseada contra la malla de colisión;
  si impacta antes, la distancia efectiva es `impacto − collisionMargin` (mínimo 0,5 m). La
  distancia del estado no cambia (al quitarse el obstáculo, vuelve).
- La cámara no se suaviza en la rotación; el seguimiento del objetivo sí (constante 0,08 s).

## 7. Entrada (`input.ts`) e interacción

Con `inputEnabled === false` no hay movimiento ni interacción (la cámara sí se puede girar).
El teclado se ignora si el foco está en un `INPUT`, `TEXTAREA` o elemento editable (copia
`isTypingInFormField` de `room-scene.ts`).

| Entrada | Efecto |
|---|---|
| Arrastre (puntero movido ≥ 6 px entre pulsar y soltar) | Gira la cámara |
| Rueda | Zoom (`zoomStep` por muesca) |
| Clic (< 6 px) sobre un objeto interactivo | Camina hasta él y, al llegar, emite `interact` |
| Clic (< 6 px) sobre el suelo | Camina hasta ese punto |
| W / A / S / D y flechas | Avanza respecto a la cámara (`cameraForward`); cancela ruta y objetivo pendiente |
| E o Espacio | Emite `interact` del objeto resaltado (§7.2), si lo hay |

### 7.1 Clic

`Raycaster` desde el puntero. Primero contra los objetos interactivos visibles (el más cercano
gana); si no hay, contra la malla de colisión (suelo).

- **Objeto**: destino = `nav.closest` del punto del objeto con tolerancia
  `{ plan: 1.5, height: 1.5 }`. Con destino: `nav.path(pose, destino)` y se guarda el objeto
  como pendiente. Al quedar a ≤ 1,75 m en planta del objeto (o ≤ 0,35 m si es `stepOn`), se
  cancela la ruta, el avatar se gira hacia el objeto y se emite `interact`. Sin destino o sin
  ruta: se emite `interact` de inmediato (mismo criterio que `dropItemAt` de 2D cuando no hay
  camino).
- **Suelo**: `nav.closest(punto)`; con punto, `nav.path`. Sin ruta, no pasa nada.

Un objeto es **interactivo** si `object.interactable` y su estado actual no es `"oculto"`
(`isObjectInteractive`).

### 7.2 Proximidad (`proximity.ts`, puro)

```ts
export const PROXIMITY_RADIUS = 2;         // m, en planta
export const PROXIMITY_CONE_DEG = 120;     // total, centrado en el frente del avatar
export const PROXIMITY_MAX_HEIGHT = 1.5;   // m de diferencia de altura

export function highlightedObject(
  pose: Pose,
  candidates: readonly { id: string; x: number; y: number; h: number }[],
): string | undefined;
```

El más cercano dentro del radio, del cono y de la diferencia de altura; a igual distancia
(±1e-9), el `id` menor. Un objeto a menos de 0,3 m no se descarta por el cono.

El objeto resaltado se marca con un contorno: una copia de sus mallas con
`MeshBasicMaterial({ color: 0xffe08a, side: BackSide })` y escala 1,04. Se quita al dejar de
estar resaltado. El objeto bajo el puntero (hover) se resalta igual.

### 7.3 Soltar un ítem (`dropItemAt`)

Rayo desde `(screenX, screenY)` (coordenadas de cliente) contra los objetos interactivos.

- Sin objeto: devuelve `undefined`.
- Con objeto: camina hasta él como en §7.1 con el ítem pendiente; al llegar (o de inmediato si
  no hay ruta) emite `use-item { itemId, objectId }` si `object.useItemIds?.includes(itemId)`, y
  si no `interact-direct { objectId }`. Devuelve el `objectId`.

### 7.4 Eventos

- `avatar-move`: si `emitAvatarMoves`, como mucho cada `AVATAR_MOVE_EMIT_MS` (de
  `../session/protocol`) y solo si la pose cambió más de 0,05 m o 5° desde la última emitida.
  Lleva `roomId`, `x`, `y`, `h` y `yaw`.
- El runtime **no** emite `enter-room` ni cambia de habitación solo: una puerta es un objeto
  interactivo más; quien la cruza es la capa React (7.6) al recibir `interact`.

### 7.5 `getObjectScreenFraction`

Proyecta a pantalla el centro de la caja envolvente del objeto y devuelve la fracción (0–1) del
lienzo. Si el punto queda fuera de la vista, o el objeto no está en la habitación visible,
`undefined`. En modo `headless` usa una cámara con aspecto 16:9.

## 8. Tipo del evento (`src/phaser/world-events.ts`)

En la variante `avatar-move`, añadir `h?: number; yaw?: number`. Nada más en `phaser/`.

## 9. Bucle y limpieza

- `WebGLRenderer({ antialias: true })`, `setPixelRatio(min(devicePixelRatio, 2))`, tamaño del
  `parent` con `ResizeObserver`.
- `renderer.setAnimationLoop`; `dt` limitado a 0,1 s.
- `destroy()`: para el bucle, quita los listeners, destruye navmesh, libera geometrías,
  materiales y texturas creados por el runtime (no los de la caché de GLB), elimina el `canvas`
  y el `div` del fundido.
- Con `headless: true` no se crea renderer ni bucle; se expone `tick(dt: number)` (solo en ese
  modo) para avanzar la simulación en los tests.

## Tests (`packages/game-runtime/test/three/`)

Entorno Node (sin jsdom ni WebGL). Usa el fixture 3D de `test/fixtures/room-3d.ts` y un catálogo
de prueba con `suelo` y `muro` (copia el de `packages/nav3d/test/fixtures/catalog.ts`).

  `RoomNav` falsa que bloquea, `yawOf` (0 = +y, 90 = +x, 180 = −y, 270 = −x), `turnToward` por el
  camino corto y cruzando 0/360.
- `camera.test.ts`: `orbitPosition` a distancia y ángulos conocidos; límites de `rotateOrbit` y
  `zoomOrbit`; `cameraForward` para 0°, 90°, 180°.
- `proximity.test.ts`: radio, cono, altura, desempate por id, objeto pegado al avatar.
- `nav-parts.test.ts` (en `packages/nav3d/test/`): `buildNavInputFromParts` da la misma entrada
  que `buildNavInput` para una sala equivalente.
- `room-runtime-3d.test.ts`, con `headless: true` y un `parent` mínimo falso (objeto con
  `clientWidth`, `clientHeight`, `appendChild`, `removeChild`):
  - rechaza un modelo 2D;
  - tras `ready`, `placeAvatar` + una ruta por `inspectObject`/clic simulado no aplica: en su
    lugar expón, solo en `headless`, `walkTo(point)` y `walkToObject(objectId, itemId?)` (los
    mismos métodos internos que usa el clic) y prueba con ellos que: caminar hacia un objeto
    acaba emitiendo `interact`; con un ítem que está en `useItemIds` emite `use-item`, y con
    otro, `interact-direct`;
  - `setObjectState(id, "oculto")` hace que `isObjectInteractive(id)` sea `false`;
  - con `emitAvatarMoves`, caminar emite `avatar-move` con `h` y `yaw`, no más de uno cada
    100 ms de tiempo simulado;
  - `showRoom` de una habitación inexistente lanza.
