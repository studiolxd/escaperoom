Lee antes: `docs/plan/fase-7-modo-3d.md` (§«Normas comunes»), `docs/specs/27-modo-3d.md` §4 y §8,
y el brief `docs/plan/modo-3d/7.5c-runtime-modo-edicion.md` (la API del lienzo que vas a usar).
Lee enteros, antes de empezar:

- `packages/web/src/components/room-editor/room-editor-shell.tsx`,
  `room-editor-workspace.tsx`, `room-editor-canvas.tsx`, `room-editor-palette.tsx` y
  `room-editor-room-panel.tsx` (el editor 2D: la distribución y el estilo que se copian);
- `packages/editor/src/room-doc/tool-controller.ts` (el patrón del controlador de herramientas);
- `packages/editor/src/room-doc/commands3d.ts` y `decor.ts` (los comandos);
- `packages/game-runtime/src/three/room-runtime-3d.ts` y `edit.ts` (modo edición).

## Qué entrega

Una sala 3D se edita en `/editor/:roomId` con la **misma distribución que el editor 2D**:
paleta a la izquierda, lienzo en el centro con su barra de herramientas, e inspector, panel de
habitación y validación a la derecha. Todo lo que no es el mundo (inspector de objetos, reglas,
plantillas, idiomas, validación, playtest, publicar) es el del editor 2D sin cambios.

Se toca `packages/editor` (controlador y un par de comandos), `packages/nav3d` (una función) y
`packages/web` (interfaz). No se toca `packages/game-runtime` (si falta algo en la API del
lienzo, para y pregunta).

## 1. Comandos que faltan (`packages/editor/src/room-doc/`)

### 1.1 Antorchas con altura (`decor.ts`)

- `addTorch(doc, roomId, torch)`: en una sala 3D acepta `h` (opcional) y comprueba la posición
  con `assertInside3D` (con `h ?? 1.6`) en lugar de la comprobación de celda.
- `TorchPatch` gana `h?: number`; `updateTorch` lo aplica (solo en 3D; en 2D se ignora).
- En 2D nada cambia.

### 1.2 Lote en una transacción (`commands3d.ts`)

```ts
export type Transform3DChange =
  | { kind: "piece"; id: string; x: number; y: number; h: number; yaw: number; scale?: number }
  | { kind: "object"; id: string; x: number; y: number; h: number; yaw: number; scale?: number }
  | { kind: "spawn"; id: string; x: number; y: number; h: number; yaw: number }
  | { kind: "torch"; index: number; x: number; y: number; h: number };

/** Aplica todos los cambios en UNA transacción (un gesto del gizmo = un paso de historial). */
export function applyTransforms3D(doc: Y.Doc, roomId: string, changes: readonly Transform3DChange[]): void;

/** Duplica piezas y objetos desplazándolos `offset`. Los objetos reciben id nuevo con
 *  `proposeObjectId`. Devuelve los ids creados. No duplica spawns ni antorchas. */
export function duplicate3D(doc: Y.Doc, roomId: string,
  targets: readonly ({ kind: "piece"; id: string } | { kind: "object"; id: string })[],
  offset: { x: number; y: number; h: number }):
  { pieces: string[]; objects: string[] };
```

Usan por dentro `updatePiece3D`, `setObjectTransform`, `setSpawnPoints3D` y `updateTorch` (o su
lógica), con sus mismas comprobaciones. Si un cambio falla, no se aplica ninguno.

Al duplicar un objeto se copian sus estados, tipo, sprite e `interactable`, pero **no**
`lockedBy`, `leadsTo`, `inventory` ni `hidingSpot`.

## 2. Controlador (`packages/editor/src/room-doc/tool-controller-3d.ts`, nuevo)

Sin React ni Three; exportado desde `room-doc/core.ts`. Mismo patrón que `EditToolController`
(`subscribe`, `getState`, estado inmutable, `error?: ToolError`).

```ts
export const EDIT_TOOLS_3D = ["select", "place", "spawn", "torch"] as const;
export type EditTool3D = (typeof EDIT_TOOLS_3D)[number];

export type EditTarget = // misma forma que EditTarget3D del runtime, redeclarada aquí
  | { kind: "piece"; id: string } | { kind: "object"; id: string }
  | { kind: "spawn"; id: string } | { kind: "torch"; index: number };

export type Tool3DState = {
  tool: EditTool3D;
  roomId: string;
  /** Modelo elegido en la paleta y cómo se coloca. */
  placing?: { model: string; as: "piece" | "object"; snap: boolean };
  /** Giro con el que se coloca lo siguiente (múltiplos de 90 con imán). */
  placeYaw: number;
  workHeight: number;                 // múltiplos de 0.2, de 0 a MAX_WORLD3D_HEIGHT
  snapEnabled: boolean;               // por defecto true
  gizmoMode: "translate" | "rotate" | "scale";
  selection: EditTarget[];
  /** Fantasma que debe pintar el lienzo, o `undefined`. */
  ghost?: { model: string; x: number; y: number; h: number; yaw: number };
  lastPlacedObjectId?: string;
  error?: ToolError;
};

export type Pointer3D = {
  type: "move" | "down" | "up" | "click";
  point: { x: number; y: number; h: number } | null;
  target: EditTarget | { kind: "none" };
  shiftKey: boolean; altKey: boolean;
};

export class Edit3DController {
  constructor(doc: Y.Doc, options: { roomId: string });
  subscribe(listener: () => void): () => void;
  getState(): Tool3DState;
  setRoom(roomId: string): void;                       // limpia selección y fantasma
  setTool(tool: EditTool3D): void;
  selectModel(model: string, as: "piece" | "object", snap: boolean): void;   // pasa a "place"
  setWorkHeight(h: number): void;
  setSnapEnabled(enabled: boolean): void;
  setGizmoMode(mode: Tool3DState["gizmoMode"]): void;
  rotatePlacement(): void;                             // placeYaw += 90 (mod 360)
  select(targets: readonly EditTarget[]): void;
  pointer(event: Pointer3D): void;
  /** Del gizmo: con `final`, escribe en el doc con `applyTransforms3D`. */
  transform(changes: readonly Transform3DChange[], final: boolean): void;
  deleteSelection(): void;
  duplicateSelection(): void;                          // desplaza (1, 0, 0) y selecciona las copias
  clearError(): void;
}
```

Comportamiento de `pointer`:

- **Imán de colocación**: activo si `snapEnabled && placing.snap && !event.altKey`. Con imán, el
  punto se ajusta al centro de celda (`Math.floor(v) + 0.5` en `x` e `y`) y `h = workHeight`.
  Sin imán, el punto tal cual, con `h = workHeight`.
- **`place`**:
  - `move`: actualiza `ghost` (modelo, punto ajustado, `placeYaw`). Sin `point`, sin fantasma.
  - `down` con una **pieza**: empieza un trazo. Coloca la pieza (`placePieces3D`) y recuerda la
    celda. Los `move` siguientes, mientras no llegue `up`, colocan una pieza en cada celda nueva
    que se pise (una por celda y trazo). Antes de colocar, si ya hay en esa habitación una pieza
    con el mismo `model` a menos de 0,01 m de esa posición, se salta.
  - `click` con un **objeto**: `placeObject3D` (tipo `"decorativo"`, `interactable: true`),
    selecciona el objeto creado, guarda `lastPlacedObjectId` y vuelve a la herramienta `select`.
- **`select`**:
  - `click` sobre algo: lo selecciona; con Mayús, lo añade o lo quita de la selección.
  - `click` sobre nada: vacía la selección.
- **`spawn`**: `click` añade un punto de aparición en el punto ajustado (id `spawn-N`, con `N` el
  primer entero libre; `yaw = placeYaw`), con `setSpawnPoints3D`. Como mucho 8 por habitación:
  si ya hay 8, `error` con código `INVALID_VALUE`.
- **`torch`**: `click` añade una antorcha con `addTorch` en `(x, y)` del punto y
  `h = workHeight + 1.6`.
- Cualquier `RoomDocError` de un comando acaba en `state.error` (con `toToolError`), no se
  propaga.

`deleteSelection`: piezas con `removePieces3D`; objetos con `removeObject` (si lanza
`REFERENCED_ID`, se queda en `error` y no se borra nada más); spawns con `setSpawnPoints3D` sin
ellos (nunca deja la habitación sin ninguno: si se intentaría, `error` `INVALID_VALUE`);
antorchas con `removeLight`, de mayor a menor índice. Todo en una transacción.

## 3. Alcance en la navmesh (`packages/nav3d/src/reach.ts`, nuevo)

```ts
export type ReachIssue =
  | { code: "spawn_off_navmesh"; spawnId: string }
  | { code: "object_unreachable"; objectId: string }
  | { code: "no_floor" };

/** Requiere `initNav3D()`. `no_floor` si la navmesh está vacía (y nada más). */
export function checkRoomReach(pkg: RoomPackage, roomId: string,
  catalog: Models3DCatalog | undefined): ReachIssue[];
```

- `spawn_off_navmesh`: `nav.closest(spawn)` es `null`.
- `object_unreachable`: objeto `interactable` sin punto de navmesh con tolerancia
  `{ plan: 1.5, height: 1.5 }`, o sin ruta desde el primer spawn válido hasta ese punto.
- Destruye la navmesh antes de devolver.

## 4. Interfaz (`packages/web/src/components/room-editor/`)

### 4.1 Elegir editor

`room-editor-shell.tsx`: donde hoy se crea el `EditToolController` y se pinta
`RoomEditorWorkspace`, bifurca con `roomDimension(doc)`:

- `"2d"`: exactamente lo de hoy.
- `"3d"`: crea un `Edit3DController` y pinta `RoomEditorWorkspace3D` (§4.2) con el mismo
  inspector, grafo de reglas, validación y acciones de cabecera. La selección del inspector
  (`InspectorTarget`) sale de `selection`: si hay **exactamente un** objeto seleccionado, ese;
  si no, el puzle o la regla elegidos, como hoy.

El lienzo 3D se carga con `dynamic(..., { ssr: false })`, igual que el 2D, para que el editor 2D
no descargue Three.js ni el 3D descargue Phaser.

### 4.2 `room-editor-workspace-3d.tsx` (nuevo)

Copia la estructura de `room-editor-workspace.tsx` (cabecera, tres columnas, pestañas mapa /
reglas, navegación de habitaciones, aviso de error abajo, `data-testid="room-editor"`), con
estas diferencias:

**Barra de herramientas** (misma fila, mismos `Button` y `EditorToolHint` que en 2D):

1. Herramientas: `select`, `place`, `spawn`, `torch` (`data-tool`).
2. Modo del gizmo (solo con `select`): tres `Button` — mover, girar, escalar
   (`data-gizmo`), con `aria-pressed`.
3. Altura de trabajo: `Button` «−», `Input` numérico (paso 0,2) y `Button` «+»
   (`data-work-height`).
4. `Switch` «Imán» (`snapEnabled`).
5. `Switch` «Ver zona transitable» (navmesh).
6. Navegación de habitaciones, a la derecha, como en 2D.

Sin selector de capas.

**Atajos de teclado** (ignorados si el foco está en un campo de texto, igual que el Supr de 2D,
y en la pestaña de reglas):

| Tecla | Acción |
|---|---|
| W / E / R | Gizmo: mover / girar / escalar (pasa a `select`) |
| Q | `rotatePlacement()` |
| Supr / Retroceso | `deleteSelection()` |
| Ctrl o Cmd + D | `duplicateSelection()` (con `preventDefault`) |
| Esc | Herramienta `select` y selección vacía |
| Alt (mantener) | Imán desactivado mientras dure |

### 4.3 `room-editor-canvas-3d.tsx` (nuevo)

Monta `RoomRuntime3D` con `mode: "edit"` y lo conecta al controlador:

- `setModel(model)` cuando cambia el modelo; `showRoom` cuando cambia la habitación.
- `onEditEvent` → `controller.pointer(...)` (convirtiendo `EditPointer3D` en `Pointer3D`).
- `onTransform` → `controller.transform(...)`.
- Del estado del controlador al lienzo: `setSelection`, `setGhost`, `setWorkHeight`,
  `setGizmoMode(tool === "select" ? gizmoMode : null)`,
  `setSnap(snapEnabled && !altPulsado ? { move: 1, yaw: 90 } : { move: 0, yaw: 0 })`,
  `setNavmeshVisible`.
- `packBaseUrl` / `packId`: con `resolvePack3DBaseUrl` (la página del editor lo calcula en el
  servidor y lo pasa, como hace la de partida con `pack3d`).

Nota del imán del gizmo: el runtime lo aplica al incremento del gesto, así que lo que ya está
alineado sigue alineado. No lo «corrijas».

### 4.4 `room-editor-palette-3d.tsx` (nuevo)

Mismo ancho, cabeceras y estilo que `room-editor-palette.tsx`. Tres pestañas (`Button` con
`role="tab"`, como las pestañas mapa / reglas):

| Pestaña | Contenido | Al elegir |
|---|---|---|
| Kit | Modelos con `category` suelo, muro o estructura, agrupados por categoría | `selectModel(id, "piece", entry.snap)` |
| Objetos | Modelos con `category` mueble, pared o suelto, agrupados por `group` (los que no tienen `group`, sueltos) | `selectModel(id, "object", false)` |
| Mis modelos | `pkg.world3d.models`. Si está vacío: texto «Aún no has subido modelos.» | `selectModel(id, "object", false)` |

Cada entrada es un `Button` con el nombre (`label` en el idioma activo, con el `id` como
respaldo), sus medidas (`w × d × hgt m`) en pequeño, y un cuadrado de color de su categoría (los
mismos colores que las cajas de sustitución del runtime: suelo `#57534e`, muro `#78716c`,
estructura `#a8a29e`, mueble `#b45309`, pared `#7c3aed`, suelto `#0891b2`, propio `#be185d`).
`aria-pressed` en el modelo activo; `data-model={id}`.

En la pestaña Objetos, un conmutador pequeño «Colocar como decoración» (`Switch`): activo,
coloca el modelo como **pieza** (sin lógica) en lugar de objeto.

El catálogo sale de `getModels3DCatalog(pkg.map.tileset)`.

### 4.5 Panel derecho

Debajo del inspector (que no cambia), en lugar de `RoomEditorRoomPanel`:

**`room-editor-selection-panel-3d.tsx`** (nuevo), visible con selección:

- Un elemento: campos numéricos (`Input` + `Label`) de `x`, `y`, `h`, giro y, si es pieza u
  objeto, escala. Al confirmar (blur o Intro) llaman a `controller.transform([...], true)`.
  Botones «Duplicar» y «Borrar».
- Varios: «N elementos seleccionados», «Duplicar» y «Borrar».

**`room-editor-room-panel-3d.tsx`** (nuevo), siempre visible:

- Medidas: `Input` de ancho y fondo en metros → `setRoomBounds3D`.
- Luz ambiente: color (`Input type="color"`) e intensidad (`Slider` 0–2) → `setAmbientLight`.
- Recuento: piezas, objetos, puntos de aparición, antorchas.
- **Avisos de zona transitable**: lista de `checkRoomReach` (recalculada 500 ms después del
  último cambio del modelo, tras `await initNav3D()`), cada uno con un `Button` que selecciona
  el elemento:
  - `no_floor`: «Esta habitación no tiene suelo transitable.»
  - `spawn_off_navmesh`: «El punto de aparición {id} está fuera de la zona transitable.»
  - `object_unreachable`: «No se puede llegar hasta {object}.»
- Nota fija: «Una tarima o plataforma aislada de 1 × 1 m no se puede pisar: junta al menos dos.»
