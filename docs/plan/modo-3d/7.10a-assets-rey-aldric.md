## 1. Qué exportar

### 1.1 Objetos de `objetos.json` (con `exportar_glb.py`, ya soporta cualquier `OBJ`)

Todas las entradas de `render`: `arca`, `armario`, `brasero`, `estatua`, `trono`, `barril`,
`barriles`, `mesa`, `sarcofago`, `altar`, `relicario`, `vasijas`, `canal`, `canal-tramo`,
`compuerta`, `antorcha`, `puerta`, `reja`, `placa`, `columna`, `columna-base`,
`columna-capital`, `umbral`, `escalon`. Un GLB por estado, con el nombre de `frames`
(`armario`, `armario-abierto`, `altar-seco`, `altar-con-agua`, `puerta-cerrada`…).

Si alguna entrada falla con el exportador actual (objetos sin GLB de origen, o con imagen como
`puerta`), arréglalo en `construir.py` / `glb_comun.py`, no en los constructores del pack.

### 1.2 Objetos de suelo (`render_prop_suelo.py` es la referencia de cómo se montan)

`llave-bronce-suelo` (de `objetos/llave/tripo.glb`), `yesquero-suelo` (de
`objetos/yesquero/tripo.glb`) y `antorcha-apagada-suelo` (de
`objetos/antorcha-apagada/tripo.glb`), a la misma escala y posición tumbada que usa
`render_prop_suelo.py`. Script nuevo `scripts/blender/exportar_prop_suelo_glb.py`.

### 1.3 Piezas de pared (`scripts/blender/exportar_pared_glb.py`, nuevo)

Por cada pieza de `pared.json → piezas` (`[imagen, alto_m, altura_centro_m, grosor_m]`): un
tablero vertical con la imagen de `fuentes/pared/` como textura en la cara frontal (ancho = alto
× proporción de la imagen), grosor el indicado (0 = tela: un plano de dos caras), canto y
trasera en color oscuro neutro. Convención propia de las piezas de pared:

- origen en el **suelo**, bajo el centro de la pieza, en el plano trasero (el que toca el muro);
- la pieza queda a su `altura_centro_m`;
- frente a `+Z`.

Así, colocada con `h = 0` pegada a la cara del muro, cuelga a su altura.

Además: `cuadro-rey-torcido` (el `cuadro-rey` girado los grados de `TORCIDO` de
`blender/pared.py` alrededor de su borde superior central), y lo que `blender/pared.py`
construye para la bodega y no es una simple imagen: `compartimento-cerrado`,
`compartimento-abierto`, `ranura-vacia`, `ranura-con-caliz`. Para estos cuatro reutiliza la
geometría que arma `pared.py` (impórtalo como módulo y llama a sus funciones; no lo edites). Si
no es viable sin modificarlo, déjalos fuera y anótalo.

### 1.4 Kit (`exportar_kit.py`, ampliar)

Las piezas de la spec §4.1 que faltan, con el mismo estilo que `muro` y `suelo-piedra-1`:

| id | Cómo |
|---|---|
| `suelo-piedra-2` | como `suelo-piedra-1` con el segundo color de `estilo.json → sala.losas` y despiece distinto (una losa de 1 m con junta perimetral) |
| `suelo-alfombra` | losa con la cara superior de tela roja oscura (`#7f1d1d`) y un ribete dorado (`#b45309`) de 6 cm |
| `suelo-madera` | cinco tablas a lo largo de X con `geometria.madera`, horneada |
| `muro-ventana` | `muro` con una saetera de 0,2 × 0,8 m centrada a 1,5 m, abocinada, que no atraviesa (fondo oscuro) |
| `muro-arco` | `muro` con un hueco pasante de 0,8 × 2,0 m rematado en medio punto (`perfil_arco` de `blender/objetos.py` es la referencia de la forma) |
| `tarima` | caja de 1 × 1 × 0,4 de madera con canto de piedra |
| `rampa` | cuña de 1 × 2 que sube de 0 a 0,4 hacia `−Z`… ver nota |

## 2. Configuración por modelo (`packs/medieval-v1/modelos3d.json`, nuevo, versionado)

Fuente de todo lo que el exportador no puede medir. Forma:

```json
{
  "_": "Metadatos del catálogo 3D: categoría, grupo, nombre, colisión y alias de cada modelo.",
  "modelos": {
    "arca-cerrada": { "category": "mueble", "group": "arca", "label": { "es": "Arca cerrada", "en": "Closed chest" } },
    "puerta-cerrada": { "category": "estructura", "group": "puerta", "label": { … }, "colliders": [] }
  },
  "alias": { "puerta-madera": "puerta-cerrada" },
  "sprites2d": { "arca-cerrada-der": { "model": "arca-cerrada", "yaw": 90 } }
}
```

Reglas para rellenarlo:

- **`category`**: suelo / muro / estructura para el kit (como hoy en el catálogo); `pared` para
  todo lo de §1.3 y la antorcha; `suelto` para los objetos de suelo de §1.2, la placa y las
  vasijas; `estructura` para puerta, reja, compuerta, canal, columna, escalón y umbral; `mueble`
  para el resto.
- **`group`**: la familia de estados (el nombre de la entrada de `objetos.json`).
- **`colliders`** (opcional): si falta, una caja con la envolvente medida. Declarar `[]` en:
  puertas, rejas y compuertas (todas), placas, todo lo de categoría `pared` y `suelto`, `umbral`
  y `canal` / `canal-tramo`. El kit conserva **exactamente** los colisionadores que hoy tiene
  `medieval-v1.models3d.json` (cópialos aquí). En los estados abiertos (`arca-abierta`,
  `armario-abierto`, `relicario-abierto`) y en `brasero-encendido`, el colisionador es el del
  estado cerrado / apagado (declarado explícitamente con sus medidas).
- **`snap`**: `true` solo en las piezas de kit.
- **`alias`**: ids adicionales que apuntan al mismo fichero y metadatos (salen en el catálogo
  como entradas propias). Como mínimo, los que ya usa la sala de pruebas y el catálogo actual:
  `puerta-madera` → `puerta-cerrada`, `puerta-madera-abierta` → `puerta-abierta`,
  `placa-piedra` → `placa-arriba`.
- **`sprites2d`**: correspondencia de **cada** sprite del fixture 2D
  (`docs/reference/roompackage-rey-aldric.v1.json`: `objects[].sprite`, los sprites de sus
  estados y `decorations[].sprite`) a un modelo y un giro. Reglas, en este orden:
  1. sufijo `-der` → el mismo sprite sin sufijo, con `yaw: 90`;
  2. si el nombre es un id de modelo exportado → ese modelo, `yaw: 0`;
  3. estas equivalencias fijas: `altar` → `altar-seco`; `arca` → `arca-cerrada`; `brasero` →
     `brasero-apagado`; `barril-suelto` → `barril-cerrado`; `mesa-catas` → `mesa`;
     `placa-piedra` → `placa-arriba`; `puerta-madera` → `puerta-cerrada`; `reja` →
     `reja-cerrada`; `relicario` → `relicario-sellado`; `mural-azulejos` → `mural-desordenado`;
     `ranura-caliz` → `ranura-vacia`; `compartimento` → `compartimento-cerrado`;
  4. `oculto` no se mapea (es el estado «no visible», no un modelo): lístalo en
     `"sinModelo": ["oculto"]`.
  Si después de aplicar las reglas queda algún sprite sin modelo, **para y pregunta** con la
  lista.

## 3. Catálogo generado (`scripts/generar_catalogo_3d.mjs`, nuevo)

```
node scripts/generar_catalogo_3d.mjs            # escribe packages/shared/src/packs/medieval-v1.models3d.json
node scripts/generar_catalogo_3d.mjs --check    # falla si el fichero versionado no coincide
```

- Lee `modelos3d.json` y, por cada modelo, su GLB optimizado de
  `packages/web/public/packs/medieval-v1/models/` para medir `size` (caja envolvente, con
  `getBounds` de gltf-transform; ejes: `w` = X, `d` = Z, `hgt` = Y) y `clips`.
- Un modelo declarado cuyo GLB no existe entra en el catálogo con el `size` que declare
  `modelos3d.json` (campo opcional `size`) y, si tampoco lo declara, el script falla diciendo
  cuál.
- Colisionador por defecto: caja con la envolvente, en coordenadas lógicas
  (`cx`, `cy` = centro en X y Z; `ch` = centro en Y).
- Salida determinista: claves ordenadas, números redondeados a 3 decimales, `version` =
  `"1.0.0"`. `avatars` se conserva tal cual está hoy.
- `--check` compara solo estructura y valores (no necesita los GLB si `modelos3d.json` trae
  `size` para todos: tras generar, **escribe de vuelta** en `modelos3d.json` el `size` medido de
  cada modelo, para que `--check` funcione en un clon sin binarios).

`scripts/exportar_3d.py`: nueva opción `--todo` que exporta §1 entero, optimiza y llama al
generador. `--muestra` sigue igual.

## 4. Visor (`visor/`)

Añade un modo **galería**: un `select` con todos los modelos del catálogo (agrupados por
categoría) que muestra el elegido solo, sobre una rejilla de 1 m, con el caballero al lado como
referencia de escala (conmutable), una flecha que marca el frente (`+Z`), la caja de su
colisionador dibujada en alambre (conmutable) y sus datos (medidas, triángulos, peso, clips).
Botones «anterior» y «siguiente». La escena de muestra actual se conserva como otro modo.
