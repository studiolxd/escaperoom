# 7.8a — Modelos de creadores: validación, subida, publicación y MCP

Lee antes: `docs/plan/fase-7-modo-3d.md` (§«Normas comunes») y `docs/specs/27-modo-3d.md` §3, §4
y §9. Lee enteros: `packages/shared/src/services/intro-media.ts` (el patrón que se reutiliza),
`packages/web/src/server/rest/intro-media.ts` y sus rutas
(`packages/web/src/app/api/rooms/[roomId]/intro-media/`), y, de
`packages/shared/src/services/room-publish.ts`, `collectAssetRefs`, `rewriteAssetRefs`,
`publishedAssetKey` y `createIntroMediaPublishAssetSource`.

## Qué entrega

Un creador puede subir un GLB a su sala, el servidor lo valida y mide, el modelo queda
registrado en el documento (`world3d.models`) y se publica con la sala. Por API web y por MCP.
**Sin interfaz**: la pestaña «Mis modelos», la carga de los modelos en el runtime y el visor de
moderación son el encargo 7.8b.

Se toca `packages/shared`, `packages/editor`, `packages/web` (solo rutas de API y servicios) y
`packages/mcp-server`.

## Decisión de arquitectura

Los modelos **reutilizan el servicio y la tabla de medios de la introducción**
(`introMediaAsset`, `IntroMediaService`): mismo ciclo (reserva `pending` → PUT presignado →
`complete` valida y marca `ready`), misma referencia de borrador `media:<uuid>`, misma
resolución de URL (`resolveMediaRef`) y misma publicación (`resolveDraftAsset`). Solo se añade
un tipo más, `kind: "model"`. No hay tabla ni migración nuevas (`kind` es texto libre).

## 1. Inspector de GLB (`packages/shared/src/models3d/glb-inspect.ts`, nuevo, puro)

Sin dependencias nuevas: lee la cabecera y el JSON del GLB a mano.

```ts
export const MODEL3D_LIMITS = {
  maxBytes: 15 * 1024 * 1024,
  maxTriangles: 100_000,
  maxTextureSize: 2048,
} as const;

export const MODEL3D_ALLOWED_EXTENSIONS = [
  "KHR_materials_emissive_strength", "KHR_texture_transform", "KHR_mesh_quantization",
  "EXT_meshopt_compression", "KHR_draco_mesh_compression", "EXT_texture_webp",
  "KHR_texture_basisu",
] as const;

export type GlbIssueCode =
  | "not_glb" | "bad_version" | "truncated" | "bad_json"
  | "too_large" | "too_many_triangles" | "texture_too_large" | "texture_unreadable"
  | "extension_not_allowed" | "external_uri" | "has_cameras" | "has_lights" | "no_mesh";

export type GlbInspection =
  | { ok: false; code: GlbIssueCode; message: string }
  | { ok: true; triangles: number; textures: { width: number; height: number }[];
      clips: string[];
      /** Caja envolvente en coordenadas lógicas del modelo (x = X, y = Z, h = Y del glTF). */
      bounds: { min: { x: number; y: number; h: number }; max: { x: number; y: number; h: number } };
      size: Model3DSize;                 // w = Δx, d = Δy, hgt = Δh (mínimo 0.01 cada uno)
      /** Colisionador por defecto: una caja con la envolvente. */
      collider: Collider3D };

export function inspectGlb(bytes: Uint8Array, limits?: Partial<typeof MODEL3D_LIMITS>): GlbInspection;
```

Reglas, en este orden (la primera que falle decide):

1. `too_large`: `bytes.byteLength > maxBytes`.
2. `not_glb`: los 4 primeros bytes no son `glTF` (0x46546C67 en little-endian).
   `bad_version`: versión ≠ 2. `truncated`: la longitud de la cabecera no coincide con el
   tamaño, o los trozos no caben. El primer trozo debe ser `JSON`; `bad_json` si no se puede
   parsear.
3. `extension_not_allowed`: algo en `extensionsUsed` o `extensionsRequired` fuera de la lista
   (el mensaje dice cuál).
4. `external_uri`: algún `buffers[].uri` o `images[].uri` definido que no empiece por `data:`.
   (Un GLB válido para nosotros lo lleva todo dentro.)
5. `has_cameras`: `cameras` no vacío. `has_lights`: usa `KHR_lights_punctual` (ya cae en 3, pero
   da este código si aparece).
6. `no_mesh`: sin `meshes` o sin ninguna primitiva.
7. Triángulos: suma, por primitiva con `mode` 4 o ausente, de `accessors[indices].count / 3`
   (o `accessors[POSITION].count / 3` sin índices). Las primitivas de otros modos no suman.
   `too_many_triangles` si supera el máximo.
8. Texturas: por cada `images[]` con `bufferView`, lee ancho y alto de la cabecera del fichero
   incrustado: PNG (IHDR), JPEG (primer marcador SOF0–SOF15 salvo DHT/DAC/JPG), WebP (`VP8 `,
   `VP8L`, `VP8X`) y KTX2 (bytes 20–27). Formato no reconocido → `texture_unreadable`.
   `texture_too_large` si algún lado supera el máximo.
9. Envolvente: recorre los nodos de la escena por defecto (o la 0) acumulando su matriz
   (`matrix`, o `translation`/`rotation`/`scale`); para cada primitiva transforma las 8 esquinas
   de `accessors[POSITION].min/max` y acumula. Con `KHR_mesh_quantization` los `min`/`max` ya
   están en el espacio del accessor: aplícales la matriz igual. Sin `min`/`max` en algún
   POSITION → `bad_json`.
10. `clips`: `animations[].name` (los que no tengan nombre, `anim-<índice>`), hasta 32.
11. `collider`: `{ type: "box", cx, cy, ch, sx, sy, sh }` con el centro y el tamaño de la
    envolvente (lados mínimos de 0,01).

Mensajes en castellano, accionables («El modelo tiene 180.000 triángulos; el máximo es
100.000»). Exporta el módulo en `packages/shared/package.json` como `"./models3d"` (junto con un
`index.ts`).

## 2. Servicio (`packages/shared/src/services/intro-media.ts`)

- `IntroMediaKind`: añadir `"model"`.
- Contenido: `MODEL3D_CONTENT_TYPE = "model/gltf-binary"`. Tipo declarado aceptado:
  `model/gltf-binary`, o vacío / `application/octet-stream` con nombre terminado en `.glb`.
- Clave de borrador: `uploads/models/<roomId>/<id>.glb`.
- `PUBLISHED_KEY_RE`: admitir también la extensión `glb`.
- Métodos nuevos, calcados de los del vídeo:

```ts
export type ModelUploadResult = {
  ref: string;                           // "media:<uuid>"
  size: Model3DSize; colliders: Collider3D[]; clips: string[];
  triangles: number; byteSize: number;
};

createModelUpload(actor, roomId, input: { filename: string; contentType: string; byteSize: number }): Promise<VideoUploadTicket>;
completeModelUpload(actor, roomId, assetId): Promise<ModelUploadResult>;
uploadModelBytes(actor, roomId, input: { filename: string; contentType: string; bytes: Uint8Array }): Promise<ModelUploadResult>;
/** Vuelve a medir un modelo ya `ready` (para el visor de moderación y el editor). */
describeModel(access: IntroMediaAccess, ref: string): Promise<ModelUploadResult>;
```

- `createModelUpload`: solo el autor; tamaño declarado ≤ `MODEL3D_LIMITS.maxBytes`
  (`PAYLOAD_TOO_LARGE` si no).
- `completeModelUpload`: como el del vídeo (HEAD, tamaño real ≤ límite), pero en lugar del
  *sniff* lee el objeto entero (`readRange(key, 0, size − 1)`) y llama a `inspectGlb`. Si
  `ok: false`: borra objeto y asset y lanza `IntroMediaError` — `PAYLOAD_TOO_LARGE` para
  `too_large`, `UNSUPPORTED_MEDIA_TYPE` para `not_glb` / `bad_version` / `truncated` /
  `bad_json`, y `VALIDATION_ERROR` (con el mensaje del inspector) para el resto. Idempotente
  sobre un asset ya `ready` (vuelve a inspeccionar para devolver los metadatos).
- `uploadModelBytes`: mismas comprobaciones sobre los bytes; nace `ready`.
- `describeModel`: resuelve la clave con `resolveMediaRef(access, ref)`, comprueba que es un
  `.glb`, lee e inspecciona.
- `resolveMediaRef` y `resolveDraftAsset` ya sirven para `kind: "model"` sin cambios (compruébalo
  con tests).

## 3. Publicación (`packages/shared/src/services/room-publish.ts`)

- `collectAssetRefs`: añadir `pkg.world3d?.models[*].ref` (los que casen con
  `INTRO_MEDIA_REF_RE`).
- `rewriteAssetRefs`: reescribir también esos `ref`.
- `publishedAssetKey`: admite `model/gltf-binary` → extensión `glb`.
- El reparto de `createCompositePublishAssetSource` ya manda los `media:` a la fuente de medios.

Tests: publicar una sala 3D con un modelo propio copia el GLB a
`assets/rooms/<roomId>/<sha256>.glb` y la versión publicada lleva `r2://…glb` en
`world3d.models[id].ref`; con un `media:` que no está `ready`, la publicación se rechaza como
con un vídeo sin completar.

## 4. Comandos del documento (`packages/editor/src/room-doc/commands3d.ts`)

```ts
/** Registra (o sustituye) un modelo propio. `id` cumple ID_PATTERN y no puede coincidir con un
 *  modelo del catálogo del pack (`catalogIds`). Tope: MAX_WORLD3D_CUSTOM_MODELS. */
export function setCustomModel3D(doc: Y.Doc, id: string, model: CustomModel3D,
  opts?: { catalogIds?: ReadonlySet<string> }): void;

/** Quita un modelo propio. Lanza REFERENCED_ID si alguna pieza lo usa como `model` o algún
 *  objeto como `sprite` o sprite de estado (lista los 3 primeros). */
export function removeCustomModel3D(doc: Y.Doc, id: string): void;

export function listCustomModels3D(doc: Y.Doc): (CustomModel3D & { id: string })[];
```

Errores: id inválido → `INVALID_ID`; id de catálogo o tope superado → `INVALID_VALUE`; quitar
uno inexistente → `UNKNOWN_OBJECT` no: añade el código `"UNKNOWN_MODEL"` a `RoomDocErrorCode`.
Solo en salas 3D (`assertDimension`).

## 5. API web (`packages/web`)

Rutas nuevas bajo `src/app/api/rooms/[roomId]/models/`, con handlers en
`src/server/rest/room-models.ts` (calcados de `rest/intro-media.ts`: mismo actor, mismos códigos
HTTP, mismo formato de error):

| Ruta | Qué hace | Política de cuota |
|---|---|---|
| `POST /api/rooms/:roomId/models` | cuerpo `{ filename, contentType, byteSize }` → `createModelUpload` → `{ assetId, uploadUrl, headers }` | la de `intro-media/video` |
| `POST /api/rooms/:roomId/models/:assetId/complete` | `completeModelUpload` → `ModelUploadResult` | la de su equivalente de vídeo |
| `GET /api/rooms/:roomId/models/url?ref=…` | URL firmada de lectura (`resolveMediaRef` con el actor) → `{ url }` | `intro-media-read` |

No registran el modelo en el documento: eso lo hace el cliente (editor o MCP) con
`setCustomModel3D`. Documenta las tres rutas en `docs/specs/13-api-rest.md` junto a las de
`intro-media`.

## 6. MCP (`packages/mcp-server`)

### 6.1 `upload` (`src/tools/upload.ts`)

- `kind` gana `"model3d"`. Exige `roomId` y además `modelId` (parámetro nuevo, `ID_PATTERN`,
  «id con el que se usará el modelo en `sprite`, estados y `place_pieces`») y `label`
  (opcional; por defecto el nombre del fichero sin extensión).
- Tope de transporte: el de siempre (10 MB). Cuota: la misma política que `intro_video`.
- Flujo: `introMedia.uploadModelBytes(...)` y, con el resultado, una mutación del borrador con
  `mutateDraft` que llama a `setCustomModel3D(doc, modelId, { ref, label, size, colliders, clips }, { catalogIds })`
  (`catalogIds` del catálogo del pack de la sala). Si la mutación falla, el asset subido se
  queda (no se borra) y el error se devuelve tal cual.
- Texto de éxito: `✅ upload — modelo "<modelId>" subido (<w>×<d>×<hgt> m, <triangles> triángulos, clips: …). Úsalo como sprite en add_object o como model en place_pieces.`
- En una sala 2D: el error `WRONG_DIMENSION` ya se traduce (7.9).
- Actualiza la `description` de la tool con el nuevo tipo y sus límites (GLB, 15 MB en la web y
  10 MB por aquí, 100.000 triángulos, texturas de 2048 px, sin cámaras ni luces).

### 6.2 `remove_model` (tool nueva, fase `content`)

Entrada `{ roomId, modelId, dryRun }` → `removeCustomModel3D`. `REFERENCED_ID` y
`UNKNOWN_MODEL` se traducen en `roomDocErrorToToolError` (el segundo a `NOT_FOUND`).

### 6.3 `get_model_catalog`

Ya lista los modelos propios (7.9); comprueba con un test que aparece uno recién subido.

Actualiza `docs/specs/10-mcp-del-creador.md`.

## Criterios de aceptación

- `pnpm verify:pr` en verde. Los tests existentes de medios de la introducción, audio y
  publicación no cambian sus expectativas.
- Ninguna dependencia nueva.

## Fuera de alcance

Interfaz del editor, carga de modelos propios en el runtime, visor de moderación (todo en
7.8b). Conversión u optimización del GLB subido: se guarda tal cual.
