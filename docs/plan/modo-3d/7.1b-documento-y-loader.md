# 7.1b — Documento del editor y modelo del runtime en 3D

Lee antes: `docs/plan/fase-7-modo-3d.md` (§«Normas comunes») y `docs/specs/27-modo-3d.md` §2, §3
y §8.1. Requiere 7.1a integrado.

## Qué entrega

El documento Yjs de la sala guarda un mundo 3D y lo convierte de ida y vuelta a `RoomPackage`.
Existen los comandos 3D que usarán el editor y el MCP. El modelo del runtime (`RuntimeModel`)
lleva los datos 3D. No hay interfaz ni render todavía.

Se toca `packages/editor/src/room-doc/` y `packages/game-runtime/src/loader/`.

## 1. Forma del documento (`room-doc/doc-model.ts`)

Añadir a `ROOM_DOC_KEYS`:

```ts
pieces3d: "pieces3d",   // Y.Map<pieceId, Y.Map>: roomId, model, x, y, h, yaw, scale?, order
models3d: "models3d",   // Y.Map<modelId, Y.Map>: ref, label, size, colliders, clips, order
```

- `meta` gana la clave `dimension` (`"2d"` | `"3d"`). Solo se escribe si la sala es 3D.
- Añadir `"pieces3d"` y `"models3d"` al tipo `RecordCollection`.
- Actualizar el comentario de cabecera con las dos colecciones.
- `CURRENT_ROOM_DOC_FORMAT` no cambia: un documento sin estas raíces es un documento 2D válido.

Las piezas van en una colección plana por id (no anidadas por habitación) para que dos personas
editando piezas distintas nunca choquen.

## 2. Serialización (`room-doc/serialize.ts`)

### 2.1 `RoomPackage` → documento (`roomPackageToDoc`)

- Si `pkg.meta.dimension` está definido, `meta.set("dimension", ...)`.
- Vaciar siempre `pieces3d` y `models3d` (añadirlas a `ROOT_COLLECTIONS`).
- Por cada habitación de `pkg.world3d?.rooms` y cada pieza: `pieces3d.set(piece.id,
  buildFlatRecord({ ...piece, roomId }, order))`, con `order` creciente en el orden del paquete
  (habitaciones en el orden de `map.rooms`, piezas en su orden).
- Por cada entrada de `pkg.world3d?.models`: `models3d.set(id, buildFlatRecord(model, order))`.

Los objetos ya se guardan con `buildFlatRecord`, así que `transform` viaja sin cambios. Los
`spawnPoints` y `lighting` son JSON, así que `h` y `yaw` también.

### 2.2 Documento → `RoomPackage`

- `readMeta`: incluir `dimension` solo si la clave existe y vale `"2d"` o `"3d"` (ida y vuelta
  exacta: una sala sin la clave no la gana).
- Nueva `export function buildRoomWorld3D(doc: Y.Doc): World3D`: agrupa `pieces3d` por `roomId`
  (en orden `order`), quita `roomId` y `order` de cada pieza, y lee `models3d`. Incluye una
  entrada `rooms[roomId] = { pieces: [] }` por cada habitación del documento, aunque no tenga
  piezas.
- `roomDocToPackage`: añadir `world3d: buildRoomWorld3D(doc)` **solo si** `meta.dimension ===
  "3d"`.

## 3. Metadata (`room-doc/commands.ts`)

- `writeRoomMeta`: si `input.dimension === "3d"`, `meta.set("dimension", "3d")`. Con `"2d"` o
  ausente no escribe la clave.
- Nueva `export function roomDimension(doc: Y.Doc): RoomDimension` (lee `meta.dimension`;
  ausente = `"2d"`).
- `RoomDocErrorCode`: añadir `"WRONG_DIMENSION"` y `"UNKNOWN_PIECE"`.
- Nueva `export function assertDimension(doc: Y.Doc, expected: RoomDimension, what: string): void`
  que lanza `RoomDocError("WRONG_DIMENSION", "<what> solo existe en salas <expected>")`.

No existe ni debe existir un comando que cambie la dimensión de un documento ya creado.

## 4. Comandos 2D que no valen en 3D

Llamar a `assertDimension(doc, "2d", "<nombre>")` al principio de la transacción en:
`paintTiles`, `eraseTiles`, `fillTiles`, `placeObject`, `moveObject` (commands.ts);
`addDecoration`, `moveDecoration`, `setDecorationSprite`, `removeDecoration`, `setDecorations`
(decor.ts); y `setSubRoomGrid` (content.ts) **solo cuando recibe `layers`**. Sin `layers`,
`setSubRoomGrid` vale en 3D (es `setRoomBounds3D`). `setTileset` vale en las dos dimensiones.

Siguen valiendo en 3D sin cambios: `removeObject`, `renameObject`, `findIdReferences`, las luces
(`addTorch`, `updateTorch`, `removeLight`, `setAmbientLight`, `setLighting`), ítems, puzles,
diálogos, pistas, reglas, idiomas, introducción y duración.

Ajustes en 3D:

- `defineSubRooms` y `setSubRoomGrid`: en 3D crean la habitación con `layerNames` vacío y sin
  tiles. El spawn por defecto de una habitación nueva es
  `{ id: "spawn-1", x: cols / 2, y: rows / 2, h: 0, yaw: 0 }`. Al encoger, además de lo que ya
  comprueba `assertNothingLeftOutside`, comprobar las piezas de `pieces3d` de esa habitación
  (mismo error `OUT_OF_BOUNDS`, citando cuántas piezas quedarían fuera).
- `addObject` en 3D: exige `object.transform` (si falta: `RoomDocError("INVALID_VALUE", ...)`),
  comprueba que está dentro de la habitación (§5) y **sobrescribe** `object.position` con
  `positionFromTransform(object.transform)` antes de guardar.
- `addLobbyRoom` / `buildLobbyRoom` (lobby-intro.ts) en 3D: la habitación se crea sin capas y sus
  piezas (suelo interior y muro perimetral) se añaden a `pieces3d` con la misma disposición que
  `withLobbyRoom` de `shared` en 3D (brief 7.1a §4), ajustada al tamaño pedido. Usa ids
  aleatorios (§5), no los deterministas de `shared`.

## 5. Comandos 3D (`room-doc/commands3d.ts`, nuevo)

Exportarlo desde `room-doc/core.ts`. Todos empiezan con `assertDimension(doc, "3d", ...)` y hacen
una sola transacción.

```ts
export type Piece3DInput = Omit<Piece3D, "id">;

/** "p-" + 8 caracteres [a-z0-9] aleatorios, libre en el documento. */
export function newPieceId(doc: Y.Doc): string;

/** x ∈ [0, cols], y ∈ [0, rows], h ∈ [0, MAX_WORLD3D_HEIGHT]; si no, OUT_OF_BOUNDS. */
export function assertInside3D(doc: Y.Doc, roomId: string,
  p: { x: number; y: number; h: number }): void;

export function setRoomBounds3D(doc: Y.Doc, roomId: string, grid: Grid): void;   // = setSubRoomGrid

export function placePieces3D(doc: Y.Doc, roomId: string,
  pieces: readonly Piece3DInput[]): string[];                    // devuelve los ids

export function updatePiece3D(doc: Y.Doc, pieceId: string,
  patch: Partial<Piece3DInput>): void;                           // UNKNOWN_PIECE si no existe

export function removePieces3D(doc: Y.Doc, pieceIds: readonly string[]): number;  // borradas

export function fillPieces3D(doc: Y.Doc, roomId: string, input: {
  model: string;
  from: { x: number; y: number };     // celdas enteras, ambas incluidas
  to: { x: number; y: number };
  h: number;
  yaw?: number;                       // por defecto 0
}): string[];                         // una pieza por celda, en (i + 0.5, j + 0.5, h)

export function listPieces3D(doc: Y.Doc, roomId?: string): (Piece3D & { roomId: string })[];

export function placeObject3D(doc: Y.Doc, input: {
  roomId: string; sprite: string; transform: Transform3D;
  id?: string; type?: string; interactable?: boolean;
}): string;                           // como placeObject, con transform y position derivada

export function setObjectTransform(doc: Y.Doc, objectId: string,
  transform: Transform3D, roomId?: string): void;                // actualiza transform y position

export function setSpawnPoints3D(doc: Y.Doc, roomId: string,
  spawns: readonly { id: string; x: number; y: number; h: number; yaw: number }[]): void;
```

Reglas comunes:

- Habitación inexistente: `UNKNOWN_ROOM` (usa `subRoom(doc, roomId)`).
- Toda posición pasa por `assertInside3D`.
- `yaw` fuera de `[0, 360)` o `scale` fuera de `[MIN_SCALE_3D, MAX_SCALE_3D]`: `INVALID_VALUE`.
- `model` y `sprite` deben cumplir `ID_PATTERN`: `INVALID_ID`. No se comprueba aquí que el
  modelo exista en el catálogo (lo avisa el validador).
- `placePieces3D` y `fillPieces3D`: si la habitación superaría `MAX_WORLD3D_PIECES_PER_ROOM`,
  `INVALID_VALUE` y no se escribe nada.
- `fillPieces3D` no borra ni deduplica lo que ya haya en esas celdas.
- Los ids de pieza son un espacio propio: no entran en `usedIds`.
- Al borrar una habitación (si existe un comando que lo haga) se borran sus piezas.

## 6. Modelo del runtime (`packages/game-runtime/src/loader/`)

`types.ts`:

```ts
// RuntimeModel
dimension: "2d" | "3d";
/** Modelos propios de la sala (specs/27 §9); {} en 2D. */
customModels: Record<string, { ref: string; size: Model3DSize; colliders: Collider3D[]; clips: string[] }>;

// RuntimeSubRoom
pieces: Piece3D[];                    // [] en 2D

// RuntimeObject
transform?: Transform3D;

// RuntimeSpawn
h: number;                            // 0 si falta
yaw: number;                          // 0 si falta

// RuntimeTorchLight
h?: number;
```

`load.ts` (`toRuntimeModel`): rellenar esos campos. En 3D, `width`/`height` siguen siendo
`grid.cols`/`grid.rows`, `layers` y `decorations` quedan `[]`, y la comprobación de «posición
dentro de la rejilla» que ya hace con `position` sigue igual. `toPublicRuntimeModel` conserva los
campos nuevos.

No tocar nada de `src/phaser/`.

  los de §5 en uno 2D; `addObject` en 3D deriva `position`.

- `loader-3d.test.ts`: el modelo de una sala 3D lleva `dimension`, `pieces`, `transform`, `h` y
