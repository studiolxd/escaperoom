# 7.5b — Runtime 3D: API para la web, táctil, observador y calidad

Lee antes: `docs/plan/fase-7-modo-3d.md` (§«Normas comunes»), `docs/specs/27-modo-3d.md` §7 y el
brief anterior `docs/plan/modo-3d/7.5a-runtime-3d.md`. Requiere 7.5a integrado (lo está): lee
`packages/game-runtime/src/three/` entero antes de empezar.

## Qué entrega

Lo que le falta a `RoomRuntime3D` para que la web pueda montar una partida completa: caminar por
encargo, entrada táctil, cámaras de observador y calidad automática. El **modo edición** no
entra aquí (irá en 7.5c).

Solo se toca `packages/game-runtime/src/three/` y sus tests. La interfaz (joystick, botones,
selectores) la pondrá la web en 7.6: aquí solo va la API y la lógica.

## 1. Caminar por encargo (API pública)

Hoy `walkTo` y `walkToObject` existen pensados para los tests. Pasan a ser API pública normal
(también fuera de `headless`), con aviso de llegada:

```ts
/** Camina por la navmesh hasta el punto más cercano a `point`. `onArrive` se llama al llegar,
 *  o de inmediato si no hay ruta. Una ruta nueva, WASD o `placeAvatar` cancelan la anterior
 *  SIN llamar a su `onArrive`. Devuelve `false` si no hay ruta. */
walkTo(point: { x: number; y: number; h?: number }, onArrive?: () => void): boolean;

/** Igual que el clic sobre un objeto (brief 7.5a §7.1), con ítem opcional (§7.3). */
walkToObject(objectId: string, itemId?: string): void;
```

Si `point.h` falta, se busca con la altura actual del avatar y, si no hay punto, con tolerancia
de altura amplia (igual que ya hace `placeAvatar`).

## 2. Entrada táctil y por encargo

### 2.1 Vector de movimiento externo

```ts
/** Movimiento continuo pedido desde fuera (joystick): vector en pantalla, x = derecha,
 *  y = arriba, módulo ≤ 1. `null` = suelta. Equivale a WASD: avanza respecto a la cámara,
 *  cancela ruta y objetivo pendiente. Velocidad = WALK_SPEED × módulo (mínimo 0,3). */
setMoveVector(v: { x: number; y: number } | null): void;
```

Con WASD pulsado y vector externo a la vez, manda el teclado.

### 2.2 Gestos táctiles sobre el lienzo (`input.ts`)

Con eventos de puntero (`pointerType === "touch"`):

| Gesto | Efecto |
|---|---|
| Un dedo, movido ≥ 10 px | Gira la cámara (mismo factor que el ratón) |
| Un dedo, movido < 10 px y soltado en < 500 ms | Clic (caminar o seleccionar objeto) |
| Dos dedos (pellizco) | Zoom: cada 40 px de cambio en la distancia entre dedos = un `zoomStep` |

El lienzo lleva `touch-action: none`. El umbral de arrastre del ratón sigue en 6 px.

### 2.3 Objeto resaltado e interacción por botón

```ts
/** Id del objeto resaltado por proximidad ahora mismo, o `undefined`. */
get highlightedObjectId(): string | undefined;
/** Se llama cada vez que cambia el objeto resaltado por proximidad (no el de hover). */
onHighlightChange(handler: (objectId: string | undefined) => void): () => void;
/** Lo mismo que pulsar E: emite `interact` del resaltado. Devuelve `false` si no hay. */
interactHighlighted(): boolean;
```

## 3. Observador

Opción nueva del constructor: `observer?: boolean` (por defecto `false`). Con `observer: true`:

- No hay avatar local, ni entrada de juego (clic para caminar, WASD, E, soltar ítems), ni
  `avatar-move`. `placeAvatar`, `walkTo`, `walkToObject`, `dropItemAt` e `interactHighlighted`
  no hacen nada (devuelven `false` / `undefined`).
- Se pintan todos los jugadores de `setPlayers` que estén en la habitación visible.
- Hay dos cámaras:

```ts
export type ObserverCamera =
  | { type: "follow"; playerId: string }
  | { type: "free"; roomId?: string };

setObserverCamera(camera: ObserverCamera): void;
get observerCamera(): ObserverCamera;
/** Se llama cuando el runtime cambia de habitación por su cuenta (al seguir a un jugador). */
onObserverRoomChange(handler: (roomId: string) => void): () => void;
```

- **`follow`**: la cámara en órbita de siempre (arrastrar gira, rueda acerca, colisión con
  muros), con el objetivo en el jugador seguido. Si ese jugador pasa a otra habitación (lo dice
  `setPlayers`), el runtime hace `showRoom` de esa habitación y avisa con
  `onObserverRoomChange`. Si el jugador desaparece o se desconecta, pasa a `free` en la
  habitación actual.
- **`free`**: cámara que vuela. W/A/S/D y flechas la mueven en el plano respecto a hacia donde
  mira; Q baja y E sube; arrastrar gira (azimut y elevación entre −80° y 80°); la rueda avanza o
  retrocede. Velocidad 5 m/s. Sin colisión. Limitada a la caja de la habitación ampliada 5 m en
  cada lado y de 0,5 a 15 m de altura. Con `roomId`, hace `showRoom` de esa habitación. Al
  entrar en `free` la cámara parte de donde estaba.
  `setMoveVector` también mueve la cámara libre (para el joystick táctil).
- Estado inicial con `observer: true`: `free` en la habitación inicial, cámara en el centro de
  la habitación a 6 m de altura mirando 45° hacia abajo.

La matemática de la cámara libre va en `camera.ts` como funciones puras:

```ts
export interface FreeCameraState { x: number; y: number; h: number; azimuth: number; pitch: number }
export function moveFreeCamera(state, input: { forward: number; right: number; up: number },
  dt: number, bounds: { cols: number; rows: number }): FreeCameraState;
export function rotateFreeCamera(state, dxPx: number, dyPx: number): FreeCameraState;
```

## 4. Calidad

```ts
export type Quality3D = "high" | "low";
/** "auto" (por defecto) empieza en alta y baja sola; fijar un valor desactiva el automático. */
setQuality(quality: Quality3D | "auto"): void;
get quality(): Quality3D;
onQualityChange(handler: (quality: Quality3D) => void): () => void;
```

| | Alta | Baja |
|---|---|---|
| `pixelRatio` | `min(devicePixelRatio, 2)` | 1 |
| Sombras | `DirectionalLight.castShadow`, mapa de 2048, `PCFSoftShadowMap`; piezas y objetos reciben y proyectan | sin sombras |
| Antialias | el del renderer | igual (no se recrea el renderer) |
| Luces de antorcha simultáneas | 8 | 4 |

**Automático** (función pura en un módulo nuevo `quality.ts`):

```ts
/** Media móvil de FPS; devuelve "low" cuando la media de los últimos 5 s cae de 30. */
export function createQualityMonitor(): {
  sample(dtSeconds: number): void;
  /** `true` una sola vez, cuando toca bajar. */
  shouldDowngrade(): boolean;
};
```

- Solo baja, nunca sube sola. No muestrea durante los 2 s siguientes a un `showRoom` ni con la
  pestaña oculta (`document.hidden`).
- La cámara de sombras cubre la caja de la habitación.

## 5. Coste de la altura visual

Hoy la altura visual se calcula con un rayo contra toda la malla de colisión en cada fotograma,
para el avatar local y para cada remoto. Limítalo: recalcula solo cuando el personaje se haya
movido más de 0,05 m en planta desde el último cálculo, y guarda el resultado.

## Tests (`packages/game-runtime/test/three/`)

- `camera.test.ts`: `moveFreeCamera` (avanza hacia donde mira, respeta los límites de la caja y
  de altura) y `rotateFreeCamera` (límites de elevación).
- `quality.test.ts`: con 60 FPS no baja; con 20 FPS durante 5 s baja una sola vez; con 20 FPS
  durante 3 s no baja.
- `room-runtime-3d.test.ts` (headless), añadir:
  - `walkTo` llama a `onArrive` al llegar; una segunda llamada cancela la primera sin llamar a
    su `onArrive`; devuelve `false` sin ruta.
  - `setMoveVector({ x: 0, y: 1 })` avanza hacia donde mira la cámara y emite `avatar-move`;
    `null` lo detiene.
  - `onHighlightChange` avisa al acercarse y al alejarse; `interactHighlighted` emite
    `interact`.
  - Observador: sin avatar; `walkTo` devuelve `false`; `follow` de un jugador que cambia de
    habitación hace `showRoom` y avisa; si el jugador se va, pasa a `free`.
  - `setQuality("low")` cambia `quality` y avisa una vez.
- `exports.test.ts`: `quality.ts` es puro (no importa `three` ni toca el DOM).
