# 7.6 — Partida web en 3D

Lee antes: `docs/plan/fase-7-modo-3d.md` (§«Normas comunes»), `docs/specs/27-modo-3d.md` §5.3, §6
y §7, y los briefs `7.5a-runtime-3d.md` y `7.5b-runtime-tactil-observador-calidad.md`. Lee
entero `packages/game-runtime/src/three/room-runtime-3d.ts` (la API que vas a usar) y, de
`packages/web/src/components/game-session/`: `game-session-canvas.tsx`,
`game-session-shell.tsx`, `hooks/use-scene-sync.ts` y `hooks/use-game-hud.tsx`.

## Qué entrega

Una sala 3D se puede jugar en el navegador con el mismo HUD, los mismos paneles y la misma sala
de espera que una 2D: partida en red, sesión de evento, playtest y modo observador. Con ratón y
teclado, y en táctil.

Se toca `packages/web` y `packages/e2e`. **No se toca** `packages/game-runtime` (si falta algo
en la API del runtime, para y pregunta).

La sala para probar es la «Sala de pruebas 3D» del seed (`docs/reference/roompackage-demo-3d.v1.json`,
id de sala `00000000-0000-0000-0000-000000003001`).

## 1. Qué URL de modelos recibe el cliente

`packages/web/src/lib/room-preview-pack.ts`: nueva función

```ts
/** URL base de los modelos 3D del pack (`/packs/<tileset>`), o `undefined` si la carpeta
 *  `<packsRoot>/<tileset>/models` no existe. Misma resolución de `packsRoot` (incl. `PACKS_ROOT`)
 *  y misma caché por `(packsRoot, tileset)` que `resolveRoomPreviewPack`. */
export function resolvePack3DBaseUrl(tileset: string, options?: ResolveRoomPreviewPackOptions): string | undefined;
```

Con `PACKS_ROOT` apuntando a una carpeta vacía (E2E, CI) devuelve `undefined` y el runtime pinta
cajas.

`packages/web/src/lib/game-model.ts`: `GameModelPayload` gana
`pack3d?: { baseUrl?: string; packId: string }` (presente solo si `model.dimension === "3d"`), y
`buildGameModel` lo rellena. En 3D se sigue devolviendo `pack` (el 2D) si existe: el HUD lo usa
para los iconos de inventario y los retratos.

Todas las páginas que hoy pasan `pack` al shell pasan también `pack3d`:
`play/room/[roomId]`, `play/session/[sessionId]`, `dev/game-room`, `room-playtest`, y el
observador (§6). Los componentes intermedios (`RoomGame`, `EventGame`, `NetworkGame`,
`NetworkGameDev`, `RoomPlaytestShell`, `GameSessionShell`) reenvían la prop.

## 2. Canvas 3D (`components/game-session/game-session-canvas-3d.tsx`, nuevo)

Mismo contrato que `game-session-canvas.tsx` (mismas props más `pack3d`, mismo `onReady` con un
`GameSessionCanvasHandle`), montando `RoomRuntime3D` de `@escaperoom/game-runtime/three`:

```ts
new RoomRuntime3D(container, model, {
  initialRoomId, packBaseUrl: pack3d?.baseUrl, packId: pack3d?.packId,
  inputEnabled: false, emitAvatarMoves: true,
  backgroundColor: isDarkThemeActive() ? BACKGROUND_HEX.dark : BACKGROUND_HEX.light,
});
```

- `onReady` se llama cuando `runtime.ready` se resuelve.
- Tema claro/oscuro y `inputEnabled`: igual que el canvas 2D.
- Soltar ítems (`onDrop`): igual que el canvas 2D (`runtime.dropItemAt`).
- El contenedor lleva `data-dimension="3d"`.

`GameSessionCanvasHandle` (en `game-session-canvas.tsx`) gana campos **opcionales**, que solo
implementa el canvas 3D:

```ts
placeAvatar(x: number, y: number, h?: number, yaw?: number): void;   // firma ampliada
avatarPose?(): { x: number; y: number; h: number; yaw: number } | undefined;
walkTo?(point: { x: number; y: number; h?: number }, onArrive?: () => void): boolean;
setMoveVector?(v: { x: number; y: number } | null): void;
interactHighlighted?(): boolean;
onHighlightChange?(handler: (objectId: string | undefined) => void): () => void;
```

`game-session-shell.tsx`: el `dynamic()` actual se queda para 2D; añade otro `dynamic()` para el
canvas 3D (`ssr: false`) y elige con `model.dimension === "3d"`. Así una partida 2D no descarga
Three.js y una 3D no descarga Phaser. Añade un test que lo compruebe leyendo los imports:
`game-session-canvas.tsx` no importa `…/three` y `game-session-canvas-3d.tsx` no importa
`…/phaser` (salvo `import type`).

## 3. Sincronización (`hooks/use-scene-sync.ts`)

- `placeAvatar(selfX, selfY, self.h, self.yaw)` donde hoy se llama con dos argumentos.
- El umbral de corrección (hoy `> 3.5`) no cambia.
- `setPlayers` ya pasa `h` y `yaw` (7.4).

## 4. HUD (`hooks/use-game-hud.tsx`)

Un único punto de bifurcación: `const is3D = model.dimension === "3d"`.

- **`avatar-move`**: en 3D, `client.move(event.x, event.y, undefined, { h: event.h, yaw: event.yaw })`.
- **`walkTo(target, onArrive)`**: en 3D, en lugar de `walkSteps(stepsBetween(...))`:
  `const ok = handleRef.current?.walkTo?.(target, onArrive)`; si `ok` no es `true` y no se llamó
  a `onArrive`, no se hace nada más. (El runtime ya emite `avatar-move` mientras camina, así que
  el servidor recibe los pasos.) `stopWalking` en 3D no hace nada.
- **`enterRoom(targetRoomId, doorPosition)`**: en 3D, igual que hoy pero con el `walkTo` 3D: al
  llegar junto a la puerta, `client.move(0, 0, targetRoomId)`. La posición de la puerta en 3D es
  `object.transform` (`x`, `y`, `h`), no `object.position`: en el manejador de `interact` de una
  puerta abierta, pasa `object.transform ?? object.position`.
- **Mirillas** (`openPanel` de un `split_clue`): `walkTo(viewpoint)` ya usa el `walkTo` 3D.
- El resto (menú contextual, `use-item`, `interact-direct`, diálogos, inventario, pistas) no
  cambia.

## 5. Controles táctiles (`components/game-session/components/touch-controls.tsx`, nuevo)

Solo en 3D y solo si el dispositivo es táctil (`window.matchMedia("(pointer: coarse)").matches`).
Se monta dentro del shell, sobre el canvas, con `worldInputEnabled` como condición para estar
activo.

- **Joystick** (abajo a la izquierda): un círculo de 112 px con un pulgar de 48 px. Es un
  elemento decorativo que se arrastra (`div` con eventos de puntero; no es un control de
  formulario, así que no lleva componente shadcn). Mientras se arrastra, llama a
  `handle.setMoveVector({ x, y })` con el desplazamiento normalizado (zona muerta 0,15; `y`
  positivo = hacia arriba); al soltar, `setMoveVector(null)`. `touch-action: none`.
- **Botón «Interactuar»** (abajo a la derecha): `Button` de shadcn, `size="lg"`, redondo. Solo
  visible cuando hay un objeto resaltado (`onHighlightChange`). Al pulsar:
  `handle.interactHighlighted()`. Texto `t("touch.interact")`, y el nombre del objeto resaltado
  como `aria-label` (`t("touch.interactWith", { object })`).
- En escritorio no se pinta pista (decisión del usuario, 2026-10-05): se interactúa con Espacio.

Textos en el espacio de nombres del HUD de la partida, seis idiomas: `touch.interact`
(Interactuar / Interact), `touch.interactWith` (Interactuar con {object} / Interact with
{object}).

## 6. Observador (`components/event-panel/spectator-game.tsx`)

Hoy `SpectatorView` no pinta el mundo. En salas **3D** añade, encima de lo que ya muestra, un
panel con el mundo:

- Componente nuevo `components/event-panel/spectator-canvas-3d.tsx` (cargado con `dynamic`,
  `ssr: false`): `RoomRuntime3D` con `observer: true`, alimentado con `setPlayers` (todos los
  jugadores del `snapshot`) y `setObjectState` (todos los objetos), igual que hace
  `use-scene-sync` para un jugador. Alto fijo de 60 vh, bordes redondeados.
- Barra sobre el canvas con dos `Select` de shadcn:
  - **Cámara**: «Cámara libre» o «Seguir a {jugador}» (uno por jugador conectado). Llama a
    `setObserverCamera`.
  - **Habitación** (solo con cámara libre): las habitaciones del modelo. Llama a
    `setObserverCamera({ type: "free", roomId })`.
  `onObserverRoomChange` actualiza la habitación mostrada en el selector.
- La página del observador calcula `pack3d` y lo pasa.
- En salas 2D, `SpectatorView` queda exactamente como está.

Textos (`EventPanel.observer.*`, seis idiomas): `camera` (Cámara), `cameraFree` (Cámara libre),
`cameraFollow` (Seguir a {player}), `room` (Habitación).

## 7. Previsualizaciones

- `room-playtest`: funciona con el shell (§2). Compruébalo con un test del componente.
- `room-preview` y `world-preview` (páginas de creador que montan `RoomRuntime` directamente): si
  el modelo es 3D, muestran un aviso con `Alert` de shadcn —`t("preview3dUnavailable")`,
  «La previsualización de salas 3D estará disponible con el editor 3D.»— en lugar del canvas.
  No montes Phaser con un modelo 3D.
- `room-lobby-intro-dialog.tsx` (previsualización de la sala de espera en el editor): mismo
  aviso en 3D.

## 8. Personajes en el servidor

`packages/colyseus-server/src/game/avatar-pack.ts` valida `characterId` contra
`pack.config.json`. No lo toques: `caballero-m` ya está ahí, y un personaje sin modelo 3D se
pinta como maniquí.

## Tests

`packages/web/test/`:

- `room-preview-pack`: `resolvePack3DBaseUrl` con carpeta `models` presente, ausente y con
  `PACKS_ROOT` vacío.
- `game-model`: `pack3d` presente solo en 3D.
- `use-scene-sync`: en 3D `placeAvatar` recibe `h` y `yaw`.
- `use-game-hud` (o el test del shell que ya lo cubre): en 3D, `avatar-move` llama a
  `client.move` con `h` y `yaw`; `interact` sobre una puerta abierta llama a `handle.walkTo` con
  el `transform` de la puerta y, al llegar, a `client.move(0, 0, destino)`.
- `touch-controls.test.tsx`: arrastrar el joystick llama a `setMoveVector` con el vector
  normalizado y soltarlo, con `null`; el botón aparece con un objeto resaltado y llama a
  `interactHighlighted`.
- `spectator-game`: en 3D aparecen los selectores; en 2D no.
- Aislamiento de imports (§2).

En estos tests, simula (`vi.mock`) `@escaperoom/game-runtime/three`: jsdom no tiene WebGL.

`packages/e2e/tests/game.demo3d.spec.ts` (nuevo), con los mismos helpers que
`free-room-play.spec.ts`: entra en la «Sala de pruebas 3D» (gratis) y la completa en modo
sustitución (sin modelos): enciende el brasero, abre el candado con 314, usa la llave en la
puerta, cruza a la cámara e inspecciona el trono; espera la pantalla de resultados con victoria.
Para clicar objetos usa `window.__escaperoomGame.getObjectScreenFraction`, como el E2E del Rey
Aldric. Si el seed del E2E no incluye la sala de pruebas (mira `packages/e2e/support/`), añádela
ahí con el mismo fixture.

## Criterios de aceptación

- `pnpm verify:pr --e2e` en verde.
- Una partida 2D (Rey Aldric) no cambia: sus E2E pasan sin tocarlos.
- En la PR: cómo probarlo a mano (`pnpm db:seed`, entrar en la ficha de «Sala de pruebas 3D» y
  pulsar Jugar).

## Fuera de alcance

Editor 3D, modo edición del runtime, subida de modelos, cambios en `game-runtime` o en el
servidor.
